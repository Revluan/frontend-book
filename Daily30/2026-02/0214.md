# 一、ArrayBuffer 是什么？

## ✅ 定义

`ArrayBuffer` 是 JavaScript 中**表示原始二进制数据的一段内存区域**。

你可以理解为：

> 它是一个“内存块”，但你不能直接操作它。

---

## ✅ 特点

* 固定长度
* 只是一块连续内存
* 不能直接读写
* 必须通过视图（View）访问

---

## 示例

```js
const buffer = new ArrayBuffer(8); // 8字节
console.log(buffer.byteLength); // 8
```

这时你只是申请了 8 字节的内存，但无法读写。

---

# 二、TypedArray 是什么？

## ✅ 定义

TypedArray 是 ArrayBuffer 的“视图”。

它允许你：

* 以特定数据类型
* 读写 ArrayBuffer 中的内容

---

## 常见 TypedArray 类型

| 类型           | 每个元素字节数 |
| ------------ | ------- |
| Int8Array    | 1       |
| Uint8Array   | 1       |
| Int16Array   | 2       |
| Uint16Array  | 2       |
| Int32Array   | 4       |
| Float32Array | 4       |
| Float64Array | 8       |

---

## 示例

```js
const buffer = new ArrayBuffer(8);

const view = new Int32Array(buffer);

view[0] = 100;
view[1] = 200;

console.log(view); // Int32Array [100, 200]
```

---

## 内存结构示意

```
ArrayBuffer (8 bytes)
--------------------------------
| 4 bytes | 4 bytes |
--------------------------------
   100        200
```

---

# 三、DataView 是什么？

除了 TypedArray 以外，还有一个重要视图：

## DataView

它可以：

* 按任意字节偏移读取
* 控制大小端（非常重要）

```js
const buffer = new ArrayBuffer(4);
const view = new DataView(buffer);

view.setInt16(0, 256, true); // 小端
console.log(view.getInt16(0, true));
```

👉 DataView 常用于网络协议解析。

---

# 四、为什么需要 ArrayBuffer？

普通数组：

```js

```

* 数据不是连续内存
* 类型不固定
* 存在装箱/拆箱
* 性能较低

而 TypedArray：

* 连续内存
* 固定类型
* 高性能
* 可直接和 C / WebAssembly 交互

2. 什么是函数组合（Function Composition）？如何实现一个compose函数？

# 一、什么是函数组合（Function Composition）？

## ✅ 定义

函数组合就是：

> 把多个函数组合成一个函数，前一个函数的输出作为后一个函数的输入。

数学表示：

```
f(g(x))
```

也就是：

```
compose(f, g)(x) === f(g(x))
```

---

## 简单例子

```js
function add1(x) {
  return x + 1;
}

function multiply2(x) {
  return x * 2;
}
```

组合：

```js
compose(add1, multiply2)(5)
```

执行顺序：

```
add1(multiply2(5))
= add1(10)
= 11
```

⚠️ 注意顺序：**从右往左执行**

---

# 二、为什么需要函数组合？

假设你要：

* 先过滤
* 再排序
* 再格式化
* 再渲染

如果不用组合：

```js
const result = format(sort(filter(data)));
```

函数组合可以：

* 提高可读性
* 避免中间变量
* 实现管道化数据处理
* 更符合函数式思想

---

# 三、如何实现一个 compose？

---

## ✅ 基础版实现

```js
function compose(...fns) {
  return function (value) {
    return fns.reduceRight((acc, fn) => fn(acc), value);
  };
}
```

解释：

* `reduceRight` 从右往左
* 上一个函数的返回值作为下一个函数的参数

---

## 使用

```js
const result = compose(add1, multiply2)(5);
console.log(result); // 11
```

---

# 四、支持多个参数版本（进阶）

如果最后一个函数支持多个参数怎么办？

比如：

```js
function add(a, b) {
  return a + b;
}
```

升级版：

```js
function compose(...fns) {
  return function (...args) {
    return fns.reduceRight((acc, fn, index) => {
      return index === fns.length - 1
        ? fn(...acc)
        : fn(acc);
    }, args);
  };
}
```

---

# 五、更优雅写法（面试常用）

```js
const compose = (...fns) =>
  fns.reduceRight(
    (prev, cur) =>
      (...args) =>
        cur(prev(...args))
  );
```

这是函数式写法。

---

# 六、Redux 中的 compose

在 Redux 里：

```js
compose(
  applyMiddleware(thunk),
  devTools()
)
```

它的作用是：

* 把多个增强函数组合成一个

Redux 的 compose 本质也是：

```js
f(g(h(x)))
```

---

# 七、compose vs pipe 区别

| 名称      | 执行方向  |
| ------- | ----- |
| compose | 右 → 左 |
| pipe    | 左 → 右 |

---

## pipe 实现

```js
function pipe(...fns) {
  return function (value) {
    return fns.reduce((acc, fn) => fn(acc), value);
  };
}
```

使用：

```js
pipe(multiply2, add1)(5);
// 11
```

---

# 八、异步 compose（高阶）

如果函数是 Promise 呢？

```js
const composeAsync = (...fns) => (value) =>
  fns.reduceRight(
    (promise, fn) => promise.then(fn),
    Promise.resolve(value)
  );
```

---

# 九、面试标准回答模板

你可以这样说：

> 函数组合是函数式编程中的一个概念，指将多个函数组合成一个函数，前一个函数的输出作为后一个函数的输入。
>
> 数学表达是 f(g(x))。
>
> 在 JavaScript 中可以通过 reduceRight 实现：
>
> ```js
> function compose(...fns) {
>   return value =>
>     fns.reduceRight((acc, fn) => fn(acc), value);
> }
> ```
>
> 它常用于 Redux 中间件、数据管道处理等场景。

# 一、JavaScript 正则表达式常用方法

JavaScript 正则相关 API 分为两类：

---

## ✅ 1️⃣ RegExp 对象的方法

---

### ① `test()`

判断是否匹配，返回 boolean

```js
const reg = /abc/;
reg.test("abc123"); // true
```

常用于表单校验。

### ② `exec()`

返回匹配结果数组（支持捕获组）

```js
const reg = /(\d+)/;
```

### ② `matchAll()`（ES2020）

可以获取所有捕获组：

```js
const str = "a1 b2 c3";
const reg = /(\w)(\d)/g;

for (const match of str.matchAll(reg)) {
  console.log(match);
}
```

### ③ `search()`

返回匹配位置

```js
"hello123".search(/\d/); // 5
```

---

### ④ `replace()` ⭐⭐⭐（最重要）

```js
"hello 123".replace(/\d+/, (match) => {
  return Number(match) + 1;
```

### ⑤ `split()`

```js
"a,b,c".split(/,/);
```

# 二、如何实现一个模板字符串替换函数？

题目一般是：

实现：

```js
const template = "Hello {{name}}, age {{age}}";
const data = { name: "Tom", age: 18 };

render(template, data);
// Hello Tom, age 18
```

---

# 实现思路

1. 用正则匹配 `{{xxx}}`
2. 提取变量名
3. 去 data 中找值
4. replace 替换

---

## ✅ 基础实现

```js
function render(template, data) {
  return template.replace(/\{\{(\w+)\}\}/g, (match, key) => {
    return data[key];
  });
}
```

---

## 正则解析

```regex
\{\{(\w+)\}\}
```

解释：

| 部分    | 含义    |
| ----- | ----- |
| {{    | 匹配 {{ |
| (\w+) | 捕获变量名 |
| }}    | 匹配 }} |

---

# 三、增强版本（支持嵌套）

如果是：

```js
"Hello {{user.name}}"
```

实现：

```js
function render(template, data) {
  return template.replace(/\{\{([\w\.]+)\}\}/g, (match, key) => {
    return key.split('.').reduce((obj, k) => obj?.[k], data);
  });
}
```

---

# 四、再增强（防 undefined）

```js
function render(template, data) {
  return template.replace(/\{\{([\w\.]+)\}\}/g, (match, key) => {
    const value = key.split('.').reduce((obj, k) => obj?.[k], data);
    return value ?? '';
  });
}
```

# 六、完整面试回答模板

你可以这样答：

> JavaScript 正则常用方法包括：
>
> * RegExp 的 test 和 exec
> * String 的 match、matchAll、replace、search、split
>
> 其中 replace 支持回调函数，是模板替换实现的关键。
>
> 模板字符串替换可以通过正则匹配 {{key}}，然后在 replace 回调中取 data[key] 替换：
>
> ```js
> function render(template, data) {
>   return template.replace(/\{\{(\w+)\}\}/g, (_, key) => data[key]);
> }
> ```
>
> 如果需要支持嵌套路径，可以用 split('.') + reduce 实现。



4. 解释JavaScript中的BigInt类型，为什么需要它？它和Number有什么区别？

# 一、为什么需要 BigInt？

## 1️⃣ Number 的安全整数范围有限

JavaScript 的 `Number` 本质是：

> IEEE 754 双精度浮点数

最大安全整数：

```js
Number.MAX_SAFE_INTEGER
// 9007199254740991
```

最小安全整数：

```js
Number.MIN_SAFE_INTEGER
// -9007199254740991
```

超过这个范围：

```js
9007199254740991 + 1 === 9007199254740991 + 2
// true ❌
```

精度丢失。

---

## 2️⃣ 实际场景确实需要大整数

比如：

* 数据库自增 ID（雪花算法）
* 银行金额（分为单位）
* 区块链交易编号
* 高精度数学运算
* 加密算法

例如在区块链平台 Ethereum 中，很多数值远超 JS 安全整数范围。

所以 ES2020 引入了：

# BigInt

---

# 二、什么是 BigInt？

BigInt 是一种：

> 任意精度的整数类型

创建方式：

```js
const a = 123n;
const b = BigInt(123);
```

注意：必须加 `n`

---

# 三、BigInt 和 Number 的区别

| 对比      | Number   | BigInt |
| ------- | -------- | ------ |
| 类型      | 浮点数      | 整数     |
| 精度      | 53 位安全整数 | 任意精度   |
| 是否支持小数  | ✅        | ❌      |
| 是否可混合运算 | ✅        | ❌      |
| JSON 支持 | ✅        | ❌      |

---

## 1️⃣ 精度对比

```js
const a = 9007199254740993n;
console.log(a);
// 9007199254740993n
```

不会丢失精度。

---

## 2️⃣ 不能混合运算

```js
1n + 1
// TypeError ❌
```

必须统一类型：

```js
1n + BigInt(1)
```

或

```js
Number(1n) + 1
```

---

## 3️⃣ 不能表示小数

```js
1.5n // ❌
```

BigInt 只表示整数。

---

## 4️⃣ 除法不同

```js
5n / 2n
// 2n  （不会有小数）
```

直接截断。

---

# 四、typeof 区别

```js
typeof 1      // "number"
typeof 1n     // "bigint"
```

---

# 五、比较运算

可以比较，但不能混合算术运算：

```js
1n == 1     // true
1n === 1    // false
```

因为类型不同。

---

# 六、JSON 不支持 BigInt

```js
JSON.stringify({ a: 1n });
// TypeError
```

需要转成字符串：

```js
JSON.stringify({ a: 1n.toString() });
```

---

# 七、BigInt 的实际应用场景

---

## 1️⃣ 金融系统

金额用“分”为单位：

```js
const amount = 999999999999999999n;
```

避免精度丢失。

---

## 2️⃣ 数据库大 ID

比如：

* MySQL bigint
* Snowflake ID

后端返回：

```json
{
  "id": 9223372036854775807
}
```

如果用 Number 会精度丢失。

---

## 3️⃣ 区块链

在 Bitcoin 中交易金额单位是 satoshi，整数非常大。

---

## 4️⃣ 加密算法

需要大整数模运算。

---

# 八、BigInt 与 Math 不兼容

```js
Math.max(1n, 2n)
// ❌
```

因为 Math 只支持 Number。

# 十、面试标准回答模板

你可以这样回答：

> BigInt 是 ES2020 引入的一种任意精度整数类型，用来解决 Number 在超过 2^53 - 1 时精度丢失的问题。
>
> Number 是 IEEE 754 双精度浮点数，只能安全表示 53 位整数，而 BigInt 可以表示任意大的整数。
>
> 两者不能混合运算，BigInt 只支持整数，不支持小数，也不能直接用于 JSON 序列化。
>
> 常用于金融系统、区块链、大整数 ID 处理等场景。


5. 什么是Object.create()？它和new操作符创建对象有什么区别？
# 一、什么是 Object.create()？

`Object.create(proto, propertiesObject?)`

作用：

> 创建一个新对象，并指定它的原型（prototype）。

---

## 基础示例

```js
const proto = {
  say() {
    console.log("hello");
  }
};

const obj = Object.create(proto);

obj.say(); // hello
```

原型链结构：

```
obj → proto → Object.prototype → null
```

---

## 第二个参数（可选）

可以定义属性描述符：

```js
const obj = Object.create({}, {
  name: {
    value: "Tom",
    writable: true,
    enumerable: true,
    configurable: true
  }
});
```

---

# 二、Object.create 的本质

它做的事情等价于：

```js
function myCreate(proto) {
  function F() {}
  F.prototype = proto;
  return new F();
}
```

核心：

> 创建一个空对象，并把它的 [[Prototype]] 指向指定对象。

---

# 三、什么是 new 操作符？

例如：

```js
function Person(name) {
  this.name = name;
}

const p = new Person("Tom");
```

---

# new 做了什么？（重点）

`new Person("Tom")` 内部流程：

1. 创建一个空对象
2. 让这个对象的原型指向 Person.prototype
3. 执行构造函数，this 指向新对象
4. 如果构造函数返回对象，则返回该对象，否则返回新对象

等价实现：

```js
function myNew(fn, ...args) {
  const obj = Object.create(fn.prototype);
  const result = fn.apply(obj, args);
  return typeof result === "object" && result !== null
    ? result
    : obj;
}
```

---

# 四、Object.create vs new 的区别

| 对比       | Object.create | new   |
| -------- | ------------- | ----- |
| 是否执行构造函数 | ❌             | ✅     |
| 是否可传参    | ❌             | ✅     |
| 是否初始化属性  | ❌             | ✅     |
| 是否依赖函数   | ❌             | ✅     |
| 主要用途     | 原型继承          | 实例化对象 |

---

# 五、核心区别解释

---

## 1️⃣ Object.create 不执行构造函数

```js
function Person(name) {
  this.name = name;
}

const obj = Object.create(Person.prototype);

console.log(obj.name); // undefined
```

因为没有执行 Person。

---

## 2️⃣ new 会执行构造函数

```js
const p = new Person("Tom");
console.log(p.name); // Tom
```

---

# 六、典型应用场景

---

## 1️⃣ 纯原型继承

ES5 继承写法：

```js
function Parent() {}
Parent.prototype.say = function() {};

function Child() {}

Child.prototype = Object.create(Parent.prototype);
Child.prototype.constructor = Child;
```

这是标准继承方式。

---

## 2️⃣ 创建“干净对象”

```js
const dict = Object.create(null);
```

特点：

* 没有原型
* 没有 toString
* 适合作为纯字典

## new

6. JavaScript中的for...in和for...of有什么区别？如何遍历对象的所有属性（包括不可枚举属性）？

# 一、for...in 和 for...of 的区别

---

## 一句话总结

* `for...in` → 遍历“键名”（key）
* `for...of` → 遍历“值”（value，基于迭代器）

---

# 二、for...in

## ✅ 特点

* 遍历对象的 **可枚举属性**
* 包括原型链上的可枚举属性
* 返回的是 key（字符串）

---

## 示例

```js
const obj = { a: 1, b: 2 };

for (const key in obj) {
  console.log(key);
}
```

输出：

```
a
b
```

---

## ⚠️ 会遍历原型链

```js
const parent = { c: 3 };
const child = Object.create(parent);
child.a = 1;

for (const key in child) {
  console.log(key);
}
```

输出：

```
a
c   // 原型链上的
```

---

## 如何过滤原型链？

```js
for (const key in obj) {
  if (obj.hasOwnProperty(key)) {
    console.log(key);
  }
}
```

或者：

```js
Object.hasOwn(obj, key)
```

---

# 三、for...of

---

## ✅ 特点

* 遍历可迭代对象（Iterable）
* 基于 `Symbol.iterator`
* 返回的是 value

---

## 示例（数组）

```js
const arr = [1, 2, 3];

for (const value of arr) {
  console.log(value);
}
```

输出：

```
1
2
3
```

---

## 不能直接遍历普通对象

```js
const obj = { a: 1 };

for (const v of obj) {
}
// TypeError
```

因为普通对象没有 `Symbol.iterator`。

---

# 四、对比总结

| 对比      | for...in | for...of       |
| ------- | -------- | -------------- |
| 遍历内容    | key      | value          |
| 是否遍历原型  | ✅        | ❌              |
| 是否要求可迭代 | ❌        | ✅              |
| 常用于     | 对象       | 数组 / Map / Set |

3. 用 `Reflect.ownKeys()`

7. 手写实现一个深度比较函数isEqual，判断两个对象是否完全相等。

# 一、什么是“深度比较”？

```js
{ a: 1 } === { a: 1 } // false
```

因为比较的是引用地址。

深度比较需要：

> 比较结构和值是否完全相同。

---

# 二、基础版实现（适合初级面试）

```js
function isEqual(a, b) {
  // 1. 基本类型直接比较
  if (a === b) return true;

  // 2. 其中一个不是对象
  if (typeof a !== 'object' || typeof b !== 'object' || a === null || b === null) {
    return false;
  }

  // 3. 获取 key
  const keysA = Object.keys(a);
  const keysB = Object.keys(b);

  if (keysA.length !== keysB.length) return false;

  // 4. 递归比较
  for (let key of keysA) {
    if (!isEqual(a[key], b[key])) {
      return false;
    }
  }

  return true;
}
```

---

# 三、存在的问题（面试官会追问）

这个版本无法处理：

* 循环引用
* Date
* RegExp
* Map / Set
* Symbol
* 不可枚举属性
* NaN
* +0 / -0

---

# 四、进阶完整版实现（面试加分版）

---

## ✅ 处理循环引用 + 特殊对象

```js
function isEqual(a, b, visited = new WeakMap()) {
  // 1. 处理严格相等（包括 +0/-0）
  if (Object.is(a, b)) return true;

  // 2. 类型不同
  if (typeof a !== typeof b) return false;

  // 3. 非对象
  if (typeof a !== 'object' || a === null || b === null) {
    return false;
  }

  // 4. 循环引用处理
  if (visited.has(a)) {
    return visited.get(a) === b;
  }
  visited.set(a, b);

  // 5. 处理 Date
  if (a instanceof Date && b instanceof Date) {
    return a.getTime() === b.getTime();
  }

  // 6. 处理 RegExp
  if (a instanceof RegExp && b instanceof RegExp) {
    return a.toString() === b.toString();
  }

  // 7. 处理 Map
  if (a instanceof Map && b instanceof Map) {
    if (a.size !== b.size) return false;
    for (let [key, value] of a) {
      if (!b.has(key) || !isEqual(value, b.get(key), visited)) {
        return false;
      }
    }
    return true;
  }

  // 8. 处理 Set
  if (a instanceof Set && b instanceof Set) {
    if (a.size !== b.size) return false;
    for (let value of a) {
      if (!b.has(value)) return false;
    }
    return true;
  }

  // 9. 获取所有 key（包含 Symbol + 不可枚举）
  const keysA = Reflect.ownKeys(a);
  const keysB = Reflect.ownKeys(b);

  if (keysA.length !== keysB.length) return false;

  for (let key of keysA) {
    if (!keysB.includes(key)) return false;
    if (!isEqual(a[key], b[key], visited)) return false;
  }

  return true;
}
```

---

# 五、关键点解释

---

## 1️⃣ 为什么用 Object.is？

```js
Object.is(NaN, NaN) // true
```

而：

```js
NaN === NaN // false
```

还能区分：

```js

```

---

## 2️⃣ 为什么用 WeakMap？

防止循环引用：

```js

```

否则会无限递归。

WeakMap 记录已访问对象。

---

## 3️⃣ 为什么用 Reflect.ownKeys？

它会返回：

* 可枚举属性
* 不可枚举属性
* Symbol

这是最全面的方式。

# 八、面试标准回答模板

你可以这样回答：

> 基础实现可以通过：
>

8. 什么是可选链（?.）和空值合并运算符（??）？它们解决了什么问题？
这是一个**现代 JavaScript 高频面试题**，主要考察你是否理解：

* 安全访问对象
* falsy vs nullish 区别
* 语法糖本质
* 实际业务场景

我们系统讲清楚。

---

# 一、什么是可选链（Optional Chaining）`?.`

可选链是 ES2020 引入的语法。

作用：

> 当对象为 null 或 undefined 时，停止访问并返回 undefined，而不是报错。

---

## 1️⃣ 为什么需要它？

以前写代码：

```js
const city = user && user.address && user.address.city;
```

问题：

* 可读性差
* 代码冗长
* 容易写错

如果直接写：

```js
user.address.city
```

当 user 为 null 时：

```text
TypeError: Cannot read property 'address' of null
```

---

## 2️⃣ 可选链写法

```js
const city = user?.address?.city;
```

等价于：

```js
user == null ? undefined : user.address?.city
```

---

## 3️⃣ 支持的三种形式

### ✅ ① 访问属性

```js
obj?.prop
```

---

### ✅ ② 访问数组

```js
arr?.[0]
```

---

### ✅ ③ 调用函数

```js
fn?.()
```

如果 fn 不存在，不会报错。

---

# 二、什么是空值合并运算符（Nullish Coalescing）`??`

作用：

> 当左侧是 null 或 undefined 时，返回右侧值。

---

## 1️⃣ 为什么需要它？

以前常写：

```js
const name = input || "默认值";
```

问题：

如果：

```js
input = 0
```

结果：

```js
0 || "默认值"  // "默认值"
```

但 0 可能是合法值。

---

## 2️⃣ 正确写法

```js
const name = input ?? "默认值";
```

只有当：

```text
null 或 undefined
```

才会返回默认值。

---

# 三、|| 和 ?? 的区别

| 运算符 | 判断条件             |   |       |
| --- | ---------------- | - | ----- |
|     |                  |   | falsy |
| ??  | null / undefined |   |       |

---

## 示例对比

```js
0 || 100    // 100
0 ?? 100    // 0

"" || "hi"  // "hi"
"" ?? "hi"  // ""

null ?? 5   // 5
undefined ?? 5 // 5
```

---

# 四、可选链 + 空值合并组合使用

这是实际项目中最常见的：

```js
const city = user?.address?.city ?? "未知";
```

意思是：

* 如果 user 不存在 → undefined
* 如果 city 不存在 → undefined
* 最终给默认值

---

# 五、底层等价写法

```js
const city =
  user == null
    ? undefined
    : user.address == null
    ? undefined
    : user.address.city ?? "未知";
```

---

# 六、注意事项（面试会问）

---

## 1️⃣ 不能赋值

```js
obj?.a = 1 // ❌
```

可选链不能用于赋值左侧。

---

## 2️⃣ 不能和 || 混用（必须加括号）

```js
a ?? b || c  // ❌
```

必须：

```js
(a ?? b) || c
```

因为语法优先级冲突。

---

## 3️⃣ 只会短路 null/undefined

```js
false?.a  // 报错
```

因为 false 不是 nullish。

---

# 七、它们解决了什么问题？

---

## 1️⃣ 深层对象访问安全问题

防止：

```text
Cannot read property of undefined
```

---

## 2️⃣ 默认值误判问题

避免：

* 0 被当作 false
* "" 被覆盖
* false 被覆盖

---

# 八、实际应用场景

---

## 1️⃣ 接口数据

```js
const avatar = res?.data?.user?.profile?.avatar ?? defaultImg;
```

---

## 2️⃣ 回调安全调用

```js
props.onClick?.();
```

---

## 3️⃣ 表单默认值

```js
const count = value ?? 0;
```

---

# 九、和框架关系

在现代框架中非常常见：

* React
* Vue 3
* Next.js
* Node 服务端

例如在 React 项目中经常看到：

```js
props.user?.name
```

---

# 十、面试标准回答模板

你可以这样回答：

> 可选链 ?. 用于安全访问对象属性，当对象为 null 或 undefined 时返回 undefined 而不是报错。
>
> 空值合并运算符 ?? 用于提供默认值，只有当左侧为 null 或 undefined 时才返回右侧值。
>
> 它们解决了：
>
> * 深层对象访问报错问题
> * 使用 || 提供默认值时误判 falsy 值的问题
>
> 在现代前端项目中常用于接口数据处理和默认值设置。

13. React的StrictMode是什么？它会做哪些检查？为什么开发环境下有些代码会执行两次？

# 一、什么是 React 的 StrictMode？

`StrictMode` 是一个：

> 仅在开发环境生效的工具组件，用于帮助开发者发现潜在问题。

使用方式：

```jsx
import React from "react";

<React.StrictMode>
  <App />
</React.StrictMode>
```

在 React 18 项目中，通常在入口文件默认包裹。

例如在 React 官方推荐的模板中默认启用。

---

# 二、StrictMode 的作用是什么？

核心目标：

1. 发现副作用问题
2. 检测不安全的生命周期
3. 检测过时 API
4. 提前暴露并发模式问题
5. 检测意外的状态共享

⚠️ 重点：**它不会影响生产环境。**

# 三、它会做哪些检查？
## 1️⃣ 检测不安全的生命周期（类组件）

例如：

* UNSAFE_componentWillMount
* UNSAFE_componentWillReceiveProps
* UNSAFE_componentWillUpdate

这些生命周期在并发模式下不安全。

## 2️⃣ 检测过时 API

例如：

* string ref
* findDOMNode
* legacy context API

## 3️⃣ 检查副作用是否纯净 ⭐⭐⭐（最重要）

在 React 18 中，StrictMode 会：

> 故意让某些函数执行两次（开发环境）

包括：

* 函数组件本身
* useEffect 的初始化
* useState 初始化函数
* useMemo 初始化函数
* useReducer 初始化函数

# 四、为什么开发环境下代码会执行两次？

这是 React 18 引入的一个重要机制。

React 会在开发环境下：

> 模拟“挂载 → 卸载 → 再挂载”流程

目的是：

* 检查副作用是否安全
* 检查是否有资源未清理
* 为未来的并发渲染做准备

## 示例

```jsx
function Demo() {
  console.log("render");

  useEffect(() => {
    console.log("effect");

    return () => {
      console.log("cleanup");
    };
  }, []);

  return <div>Hello</div>;
}
```

在 StrictMode 下，开发环境输出：

```text
render
render
effect
cleanup
effect
```

---

## 发生了什么？

流程是：

```text
第一次挂载
→ 执行 render
→ 执行 effect

React 模拟卸载
→ 执行 cleanup

第二次挂载
→ 执行 render
→ 执行 effect
```

---

# 五、为什么要这样设计？

React 18 支持并发特性（Concurrent Features）。

在并发模式下：

* 组件可能会被“中断”
* 组件可能被丢弃
* 组件可能重新渲染

如果副作用写得不安全，就会出现：

* 重复请求
* 订阅未取消
* 内存泄漏
* 状态错乱

StrictMode 就是提前暴露这些问题。

---

# 六、哪些东西会执行两次？

在 React 18 StrictMode 下：

会双调用：

* 函数组件
* useEffect（初始化阶段）
* useState 初始化函数
* useMemo 初始化函数
* useReducer 初始化函数

不会双调用：

* 事件处理函数
* 生产环境代码

# 七、常见误区

---

## ❌ 误区1：React 有 bug？

不是。

这是刻意设计。

---

## ❌ 误区2：生产环境也会双执行？

不会。

StrictMode 只在开发环境生效。

---

## ❌ 误区3：useEffect 为什么会请求两次接口？

因为：

你没有做好“副作用幂等性”设计。

# 八、如何避免副作用重复执行？

---

## 方法1：保证副作用幂等

例如：

```jsx

  const controller = new AbortController();

  fetch("/api", { signal: controller.signal });

  return () => controller.abort();
}, []);
```

---

## 方法2：用 ref 控制（不推荐滥用）

```jsx

  if (didRun.current) return;
  didRun.current = true;

  // 执行一次
}, []);
```

但官方不推荐依赖这种方式。

# 九、和并发渲染的关系

StrictMode 的双执行，是为未来的：

* Suspense
* 并发渲染
* 可中断渲染

做准备。

在并发模式中：

组件可能：

* render 但不 commit
* 被丢弃
* 被重新 render

所以副作用必须可安全重放。

# 一、key 在 React 中的本质作用

在 React 中，`key` 的作用是：

```text
1️⃣ 元素类型（type）
2️⃣ key
```

只有：

```text
type 相同 && key 相同
```

才会复用 Fiber。

否则：

```text
卸载旧组件 → 挂载新组件
```

# 二、什么时候会重新挂载（Unmount + Mount）？

只要满足以下任意一种情况：
## 1️⃣ key 发生变化

```jsx
function App({ id }) {
  return <User key={id} />;
}
```

如果：

```js
id 从 1 变成 2
```

React 会认为：

```text
这是两个完全不同的组件
```

结果：

* 旧 User 卸载
* 新 User 挂载
* 所有 state 重置
* 所有 effect 重新执行

---

## 2️⃣ type 改变

```jsx
{
  flag ? <A key="1" /> : <B key="1" />
}
```

即使 key 相同，只要 type 不同：

```text
A !== B
```

依然会重新挂载。

---

## 3️⃣ key 不存在导致顺序错位

例如：

```jsx
{list.map(item => (
  <Item />
))}
```

没有 key 时，React 默认使用 index。

如果数组发生：

```text
头部插入
```

会导致后面所有组件错位更新。

表现为：

* state 混乱
* 输入框内容错位
* 组件看起来“重置”

---

# 三、什么时候只是更新（不会重新挂载）？

---

## 1️⃣ key 相同 + type 相同

```jsx
<User key="1" name={name} />
```

当：

```js
name 变化
```

React 会：

```text
复用组件实例
→ 更新 props
→ 触发 render
→ 执行 diff
```

不会：

* 不会重置 state
* 不会卸载组件
* 不会重新创建 Fiber

---

## 2️⃣ 列表顺序不变

```jsx
[
  <Item key="a" />,
  <Item key="b" />
]
```

只要：

* key 没变
* type 没变

即使 props 变化，也是更新。

---

# 四、一个经典面试陷阱

## 示例

```jsx
function App() {
```

每次 count 改变：


state 会清空。

# 五、React 内部判断逻辑（源码层面）

在 reconciliation 过程中：

React 会比较：

```js
oldFiber.key === newElement.key &&
oldFiber.type === newElement.type
```

如果成立：

```text
复用 Fiber
```

否则：

```text
delete oldFiber
create newFiber
```

这就是为什么：

> key 改变 == 强制重建组件

# 六、key 在列表中的真实作用

React diff 同层子节点时：

步骤：

1️⃣ 先按顺序比较
2️⃣ 不匹配时建立 key map
3️⃣ 用 key 查找可复用节点

如果没有 key：

只能用 index 比较。

这就是为什么：

> 不要用 index 作为 key（除非列表完全静态）

15. useLayoutEffect和useEffect的区别是什么？什么场景下必须使用useLayoutEffect？
**useLayoutEffect** 与 **useEffect** 的主要区别在于**执行时机**：

- **useEffect** 是**异步**的，在浏览器完成布局与绘制**之后**才执行，不会阻塞视觉更新。
- **useLayoutEffect** 是**同步**的，在 DOM 更新完成后、浏览器绘制**之前**执行，会阻塞视觉更新。

**必须使用 useLayoutEffect 的场景**：  
当需要**读取 DOM 布局信息（如元素尺寸、位置）并同步触发重新渲染**时，必须使用 `useLayoutEffect`。  
例如：在获取 DOM 元素的高度后立即更新状态，使新样式在本次绘制前生效，从而**避免页面闪烁或布局抖动**。其他情况（如数据请求、订阅事件等与布局无关的操作）应优先使用 `useEffect` 以保持性能。

16. React中如何实现组件的懒加载和预加载？Intersection Observer API如何配合使用？
在 React 中，实现组件的懒加载和预加载可以结合 **动态 `import()`** 与 **`React.lazy`**，并使用 `Intersection Observer` 精准控制加载时机。

---

### 1. 组件懒加载
使用 `React.lazy` 包裹动态 `import()`，配合 `Suspense` 展示加载中状态。
```jsx
import { lazy, Suspense } from 'react';

const LazyComponent = lazy(() => import('./MyComponent'));

function App() {
  return (
    <Suspense fallback={<div>Loading...</div>}>
      <LazyComponent />
    </Suspense>
  );
}
```

---

### 2. 组件预加载
提前调用 `import()` 下载组件代码，但暂不渲染。常用策略：
- **Hover 预加载**：用户鼠标悬停在链接或按钮上时触发。
- **空闲时间预加载**：使用 `requestIdleCallback` 或 `setTimeout`。
```jsx
const loadComponent = () => import('./MyComponent');

// 悬停时预加载
<button onMouseEnter={loadComponent}>查看详情</button>
```

---

### 3. 配合 Intersection Observer 实现视口懒加载
当组件进入视口时才加载，非常适合长列表或图片下方的模块。

**步骤：**
1. 创建一个占位元素（如 `<div ref={ref}>`），用 `useRef` 引用。
2. 在 `useEffect` 中创建 `IntersectionObserver`，监听该元素。
3. 当元素可见时，动态 `import()` 组件，并将加载状态设为 `true`。

**示例代码：**
```jsx
import { useState, useEffect, useRef, lazy, Suspense } from 'react';

// 懒加载的组件
const HeavyComponent = lazy(() => import('./HeavyComponent'));

function LazyLoadOnView() {
  const [show, setShow] = useState(false);
  const ref = useRef();

  useEffect(() => {
    const observer = new IntersectionObserver(
      ([entry]) => {
        if (entry.isIntersecting) {
          setShow(true);
          observer.disconnect(); // 加载后停止观察
        }
      },
      { threshold: 0.1 } // 10% 可见时触发
    );

    if (ref.current) {
      observer.observe(ref.current);
    }

    return () => observer.disconnect();
  }, []);

  return (
    <div ref={ref}>
      {show ? (
        <Suspense fallback={<div>Loading...</div>}>
          <HeavyComponent />
        </Suspense>
      ) : (
        <div>占位内容（未进入视口）</div>
      )}
    </div>
  );
}
```

这样，`HeavyComponent` 只有在进入视口后才会被加载和渲染，有效减少首屏资源体积。

17. 什么是React的Profiler API？如何使用它来分析组件性能？
**React Profiler API** 是 React 内置的性能分析工具，用于测量组件的渲染频率和每次渲染的“成本”（耗时），帮助识别性能瓶颈。

### 如何使用
1. **引入 Profiler 组件**：
   ```jsx
   import { Profiler } from 'react';
   ```

2. **包裹需要分析的组件树**，并设置 `id` 和 `onRender` 回调：
   ```jsx
   <Profiler id="MyComponent" onRender={onRenderCallback}>
     <MyComponent />
   </Profiler>
   ```

3. **实现 `onRender` 回调**，接收性能信息：
   ```jsx
   function onRenderCallback(
     id, // 发生提交的 Profiler 树的 id
     phase, // "mount"（首次渲染）或 "update"（重渲染）
     actualDuration, // 本次更新花费的渲染时间
     baseDuration, // 估计不使用 memoization 的渲染时间
     startTime, // 本次更新开始渲染的时间
     commitTime, // 本次更新提交的时间
     interactions // 本次更新涉及的 interactions（需配合调度器）
   ) {
     console.log({ id, phase, actualDuration });
   }
   ```

### 注意事项
- **仅开发环境有效**：生产环境默认禁用，可通过特殊构建（如 `react-dom/profiling`）启用。
- **影响性能**：Profiler 本身会带来额外开销，应仅在必要时使用。
- **可视化工具**：更推荐使用 **React DevTools** 的 Profiler 标签页，它以火焰图形式直观展示渲染耗时，无需手动编写 `onRender`。

**典型使用场景**：定位不必要的重渲染、比较优化前后的渲染耗时、分析组件挂载/更新性能。

18. React中如何处理异步状态？竞态条件（Race Condition）如何解决？
在 React 中处理异步状态通常涉及**管理加载、成功、错误三种状态**，常见方式有：

- **`useEffect` + 原生 `fetch`**：手动管理状态和清理副作用。
- **自定义 Hook**：封装复用逻辑（如 `useFetch`）。
- **状态管理库**：如 **Redux Toolkit Query** 或 **React Query**，它们内置了缓存、重试和竞态处理。

### 竞态条件的产生
当连续触发多个异步请求（如搜索输入），后发出的请求先返回，先发出的请求后返回，导致最终显示错误的数据（后发先至）。

### 解决方案
1. **使用 `AbortController` 取消过期请求**  
   在 `useEffect` 或事件处理中创建 `AbortController`，每次发起新请求前取消上一个未完成的请求。
   ```jsx
   useEffect(() => {
     const abortController = new AbortController();
     fetch(url, { signal: abortController.signal })
       .then(res => res.json())
       .then(setData)
       .catch(err => if (err.name !== 'AbortError') setError(err));
     return () => abortController.abort();
   }, [url]);
   ```

2. **使用标志位忽略过期响应**  
   利用 `useRef` 或闭包变量标记当前请求是否最新。
   ```jsx
   useEffect(() => {
     let ignore = false;
     fetchData().then(result => {
       if (!ignore) setData(result);
     });
     return () => { ignore = true; };
   }, [deps]);
   ```

3. **使用第三方库**（如 React Query）  
   它们通过请求键（query key）自动管理并发和缓存，避免手动处理。

**推荐**：对于简单场景用 `AbortController`，复杂场景直接使用专业数据获取库。

19. 如何在React中实现无限滚动加载？需要注意哪些性能问题？
在 React 中实现无限滚动加载，通常结合 **Intersection Observer API** 监听底部元素进入视口，触发数据加载并追加到列表。

### 实现步骤（核心逻辑）
```jsx
import { useState, useEffect, useRef, useCallback } from 'react';

function InfiniteScroll() {
  const [items, setItems] = useState([]);
  const [page, setPage] = useState(1);
  const [loading, setLoading] = useState(false);
  const [hasMore, setHasMore] = useState(true);
  const observerRef = useRef();
  const lastItemRef = useRef();

  // 加载更多数据
  const loadMore = useCallback(async () => {
    if (loading || !hasMore) return;
    setLoading(true);
    try {
      const newItems = await fetchData(page);
      setItems(prev => [...prev, ...newItems]);
      setHasMore(newItems.length > 0); // 根据返回判断是否还有更多
      setPage(prev => prev + 1);
    } finally {
      setLoading(false);
    }
  }, [page, loading, hasMore]);

  // 使用 Intersection Observer 监听最后一个元素
  useEffect(() => {
    if (loading) return;
    const observer = new IntersectionObserver(
      (entries) => {
        if (entries[0].isIntersecting && hasMore) {
          loadMore();
        }
      },
      { threshold: 0.1 }
    );

    if (lastItemRef.current) {
      observer.observe(lastItemRef.current);
    }

    return () => observer.disconnect();
  }, [loading, hasMore, loadMore]);

  return (
    <div>
      {items.map((item, index) => (
        <div key={item.id} ref={index === items.length - 1 ? lastItemRef : null}>
          {item.content}
        </div>
      ))}
      {loading && <div>加载中...</div>}
    </div>
  );
}
```

### 需要注意的性能问题
1. **DOM 节点过多**  
   - 问题：列表无限增长会导致页面卡顿。  
   - 解决：对于长列表，使用**虚拟滚动**（如 `react-window` 或 `react-virtualized`），只渲染可视区域的元素。

2. **重复请求**  
   - 问题：快速滚动可能触发多次 `loadMore`。  
   - 解决：用 `loading` 锁防止并发请求；Intersection Observer 已内置节流，但仍需配合锁。

3. **内存泄漏**  
   - 问题：组件卸载时观察器未断开。  
   - 解决：在 `useEffect` 的清理函数中调用 `observer.disconnect()`。

4. **图片加载**  
   - 问题：新加载的图片可能阻塞渲染。  
   - 解决：结合图片懒加载（可使用 `loading="lazy"` 或 Intersection Observer 单独处理图片）。

5. **滚动事件替代方案**  
   - 若用 `scroll` 事件代替 Intersection Observer，需添加**节流**（`throttle`）以减少计算。

6. **缓存数据**  
   - 问题：翻页后再次回到顶部重新请求。  
   - 解决：使用状态管理库（如 React Query）缓存已加载数据，避免重复请求。

**总结**：优先使用 Intersection Observer + 加载锁，数据量大时引入虚拟滚动。

20. React Testing Library和Enzyme的区别是什么？你更推荐使用哪个？为什么？
**区别**：
- **测试理念**：Enzyme 关注组件内部实现（如 state、props、实例方法），支持浅渲染隔离子组件；React Testing Library（RTL）关注组件外部行为，模拟用户操作，不暴露内部细节。

**推荐**：**React Testing Library**  
- **官方首选**：Create React App 默认集成，React 文档推荐。  
- **可维护性**：测试用户行为而非实现，重构时不易损坏，减少脆弱的测试用例。  
- **社区趋势**：更符合现代前端测试理念，生态完善。

21. Next.js中的Image组件有什么优势？它是如何优化图片加载的？
Next.js 的 **`Image` 组件**是对原生 `<img>` 的增强，主要优势及优化机制如下：

### 核心优势
- **自动优化**：根据设备尺寸和分辨率自动调整图片大小、格式（如 WebP/AVIF）。
- **懒加载**：默认开启，只有进入视口时才加载，提升首屏性能。
- **防止布局偏移**：通过强制设置 `width` 和 `height` 或 `fill` 属性预留空间，消除 CLS（Cumulative Layout Shift）。
- **响应式**：配合 `sizes` 属性生成多尺寸图片，适配不同屏幕。
- **缓存与 CDN**：优化后的图片可持久化缓存，加速重复访问。

### 优化机制
1. **尺寸适配**：基于 `srcset` 自动生成多种宽度图片，浏览器根据视口选择最佳版本。
2. **格式转换**：检测浏览器支持情况，自动将图片转换为更高效的格式（如 WebP）。
3. **按需处理**：通过内置的图像优化 API（或自定义 loader），在请求时实时调整图片质量、尺寸，无需提前准备多套资源。
4. **优先级加载**：通过 `priority` 属性标记 LCP（最大内容绘制）元素，提前加载并跳过懒加载。
5. **懒加载**：使用 Intersection Observer 实现，减少不必要的网络请求。

**使用示例**：
```jsx
import Image from 'next/image';

<Image
  src="/hero.jpg"
  alt="Hero"
  width={1200}
  height={600}
  sizes="(max-width: 768px) 100vw, 50vw"
  priority // 关键图片提前加载
/>
```

22. Next.js的中间件（Middleware）是什么？它的执行时机是什么？有哪些应用场景？
Next.js 中间件（Middleware）是一个在请求完成之前运行的函数，可以拦截传入的请求，并在响应返回前执行逻辑。

### 执行时机
- **路由匹配之前**：中间件在服务器端运行，当用户请求一个页面或 API 路由时，中间件会在路由处理之前执行。
- **全局或特定路径**：可通过配置匹配特定路径（如 `/about/*`），只对部分路由生效。

### 应用场景
- **身份验证与授权**：检查用户登录状态，未登录时重定向到登录页。
- **重定向与重写**：根据用户设备、语言或地域动态重定向到不同页面，或基于 A/B 测试重写请求路径。
- **国际化**：根据请求头中的语言偏好自动添加或重写路由前缀（如 `/en`、`/zh`）。
- **请求头修改**：添加自定义请求头（如安全策略）或修改响应头。
- **日志与监控**：记录请求信息用于分析。
- **Bot 检测**：识别爬虫并返回特定内容。

中间件让开发者能在请求生命周期早期干预，提升灵活性且无需修改业务代码。

### next-i18next 的工作原理是什么？
`next-i18next` 是一个专门为 Next.js（支持 SSR/SSG）封装的 i18n 库，基于 `i18next` 和 `react-i18next`。其核心机制：

- **服务端翻译注入**：在 `getStaticProps` 或 `getServerSideProps` 中调用 `serverSideTranslations` 函数，它会根据当前语言加载对应的命名空间翻译文件（如 `public/locales/en/common.json`），并将翻译数据作为 props 传递给页面组件。
- **SSR/SSG 时预填充**：服务端渲染或静态生成时，翻译内容已嵌入页面 HTML，无需客户端再请求。
- **客户端复用**：在 `_app.js` 中用 `appWithTranslation` 包裹组件，使客户端能够复用服务端注入的翻译资源，并保持与 `i18next` 实例同步。
- **按需加载**：只加载当前页面所需的命名空间，避免加载全部语言文件。

简言之，`next-i18next` 通过 `serverSideTranslations` 将翻译提前准备好，确保 SSR/SSG 页面直接包含翻译文本，同时客户端能无缝接管，实现高效的国际化和良好的 SEO。

24. Next.js的streaming和selective hydration是什么？它们如何提升性能？
### Streaming 和 Selective Hydration 是什么？

**Streaming（流式渲染）**  
- 服务端渲染时，无需等待整个页面完成，而是将页面拆分为多个块（chunks）逐步发送到客户端。  
- 利用 React 的 `Suspense` 组件，可以指定每个区块的 fallback（如加载中占位符），数据就绪后替换为真实内容。  
- 例如：页眉先发送，主体内容因数据请求延迟则先显示加载动画，数据到达后再流式注入。

**Selective Hydration（选择性水合）**  
- 在客户端 hydration 阶段，React 不再一次性水合整个页面，而是根据用户交互优先级，**按需选择性地水合**某些组件。  
- 如果用户点击了某个未水合的交互区域，React 会优先水合该组件及其依赖，使其尽快响应。  
- 基于 React 18 的并发特性，hydration 是可中断的，浏览器可以优先处理更高优先级的任务。

### 它们如何提升性能？

1. **Streaming 提升首屏感知速度**  
   - 减少 TTFB（首字节时间）和 FCP（首次内容绘制），因为浏览器能更早接收到部分 HTML 并开始渲染。  
   - 用户无需面对白屏，而是看到骨架屏或加载指示器，体验更流畅。

2. **Selective Hydration 提升可交互时间（TTI）**  
   - 避免整个页面 hydration 阻塞主线程，使关键交互区域（如导航栏、按钮）更快变得可响应。  
   - 用户点击某个组件时，React 会中断低优先级的 hydration，优先处理交互，实现“即时响应”。

两者结合，让 Next.js 应用既能快速显示内容，又能尽早允许用户交互，尤其适合数据依赖多、组件复杂的页面。这些特性在 Next.js 13+ 的 App Router 中默认启用（配合 `Suspense`）。

结构化数据帮助搜索引擎理解页面内容（如商品、文章、面包屑等）。通常在 `Head` 中插入 `<script>` 标签。

```jsx
import Head from 'next/head';

export default function ProductPage({ product }) {
  const structuredData = {
    '@context': 'https://schema.org',
    '@type': 'Product',
    name: product.name,
    description: product.description,
    image: product.image,
    offers: {
      '@type': 'Offer',
      price: product.price,
      priceCurrency: 'CNY',
      availability: 'https://schema.org/InStock'
    }
  };

  return (
    <Head>
      <script
        type="application/ld+json"
        dangerouslySetInnerHTML={{ __html: JSON.stringify(structuredData) }}
      />
    </Head>
  );
}
```

- 确保数据动态生成且符合 Schema.org 规范。

### 3. 生成 sitemap
Next.js 支持动态生成 `sitemap.xml`，常用方案是使用 `next-sitemap` 库或在 API 路由中生成。

**方法一：使用 `next-sitemap`（推荐）**
1. 安装：`npm install next-sitemap`
2. 在项目根目录创建 `next-sitemap.config.js`：
   ```js
   module.exports = {
     siteUrl: 'https://example.com',
     generateRobotsTxt: true, // 同时生成 robots.txt
     sitemapSize: 5000,
     exclude: ['/admin/*'], // 排除不需要的页面
   };
   ```
3. 在 `package.json` 中添加构建脚本：
   ```json
   "scripts": {
     "postbuild": "next-sitemap"
   }
   ```
   每次构建后自动生成 sitemap 和 robots.txt。

**方法二：使用 API 路由动态生成**
创建 `pages/sitemap.xml.js`（或 `app/sitemap.xml/route.js`）：
```jsx
// pages/sitemap.xml.js
const EXTERNAL_DATA_URL = 'https://example.com';

function generateSiteMap(posts) {
  return `<?xml version="1.0" encoding="UTF-8"?>
    <urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
      <url>
        <loc>${EXTERNAL_DATA_URL}</loc>
      </url>
      ${posts
        .map(({ slug }) => {
          return `
            <url>
              <loc>${`${EXTERNAL_DATA_URL}/posts/${slug}`}</loc>
            </url>
          `;
        })
        .join('')}
    </urlset>
  `;
}

export async function getServerSideProps({ res }) {
  const posts = await fetch('https://api.example.com/posts').then(res => res.json());
  const sitemap = generateSiteMap(posts);
  res.setHeader('Content-Type', 'text/xml');
  res.write(sitemap);
  res.end();
  return { props: {} };
}

export default function Sitemap() {} // 必需的默认导出
```

- **canonical 链接**：在 `Head` 中添加 `<link rel="canonical" href="https://example.com/page" />` 避免重复内容。
- **移动端优化**：Next.js 默认移动友好，但确保添加 viewport meta。
- **性能**：使用 `next/image` 优化图片，提升页面加载速度（Core Web Vitals）。

29. Webpack的HMR（热模块替换）原理是什么？它是如何工作的？
Webpack 的 HMR（Hot Module Replacement）是一种在应用运行时动态替换、添加或删除模块的技术，无需刷新整个页面，从而保持应用状态并提升开发效率。

### 核心原理
HMR 依赖于 Webpack 的运行时环境和客户端与服务器之间的通信。主要包含以下角色：
- **Webpack Compiler**：将源代码编译成 bundles，并在文件变化时重新编译。
- **HMR Server**：集成在 webpack-dev-server 中，负责通知浏览器有更新。
- **HMR Runtime**：运行在浏览器中的一小段代码，负责接收更新、加载新模块并执行替换。
- **模块依赖图**：Webpack 内部维护的模块依赖关系，用于确定更新范围。

### 工作流程
1. **文件修改**：开发者修改源代码后，Webpack 重新编译受影响的模块。
2. **发送更新信号**：编译完成后，Webpack 将更新发送给 HMR Server。HMR Server 通过 WebSocket 向客户端推送一条消息，告知有更新可用。
3. **请求更新清单**：浏览器中的 HMR Runtime 收到信号后，向服务器发送 AJAX 请求，获取本次更新的 manifest（包含哪些模块发生了变化以及新的模块 hash）。
4. **下载更新模块**：根据 manifest，HMR Runtime 再通过 JSONP 或动态脚本加载的方式下载更新后的模块代码。
5. **模块替换**：HMR Runtime 将新模块插入到模块缓存中，然后检查模块的依赖树，找出所有受影响的模块，并调用它们的 `module.hot.accept` 回调（如果存在），执行自定义的替换逻辑（如更新组件状态或重新渲染）。如果某个模块没有接受更新，HMR Runtime 会沿依赖链向上冒泡，最终可能导致页面刷新。
6. **完成更新**：成功替换后，HMR Runtime 向服务器确认更新完成。

### 关键点：模块接受更新
为了让模块支持 HMR，需要在模块代码中显式声明接受更新：
```javascript
if (module.hot) {
  module.hot.accept('./module.js', function() {
    // 当该模块或其依赖更新时，执行此处逻辑
    // 例如重新渲染组件
  });
}
```
如果没有任何模块接受更新，HMR Runtime 会触发整个页面重新加载（作为 fallback）。

### 优势
- **保持应用状态**：替换模块时，应用的当前状态（如 React 组件的 state）不会丢失。
- **快速反馈**：仅更新变化的模块，节省编译和加载时间。
- **开发体验**：与样式热替换（CSS HMR）结合，实时预览样式修改。

HMR 是 Webpack 开发服务器的核心功能之一，极大提升了前端开发效率。

32. 前端如何实现权限管理？路由级权限、按钮级权限、数据级权限如何设计？
前端权限管理通常基于用户角色或权限标识，控制用户对页面、功能和数据的访问。分为三个层级：**路由级、按钮级、数据级**，设计如下：

### 1. 路由级权限
控制用户能访问哪些页面。

- **实现方式**：  
  - 在路由配置中为每个路由添加 `meta` 字段（如 `roles` 或 `permission`），定义可访问的角色/权限。  
  - 在全局路由守卫（如 Vue Router 的 `beforeEach` 或 React Router 的自定义 `Route` 组件）中，获取当前用户权限，与路由所需权限比对，若无权限则重定向到 403 或登录页。  
  - 动态路由：登录后根据后端返回的权限路由表，使用 `router.addRoutes` 动态添加可用路由（常见于 RBAC 模型）。  

- **示例（Vue）**：  
  ```javascript
  // 路由配置
  {
    path: '/admin',
    component: Admin,
    meta: { roles: ['admin'] }
  }
  // 路由守卫
  router.beforeEach((to, from, next) => {
    const userRoles = store.state.user.roles;
    if (to.meta.roles && !to.meta.roles.some(r => userRoles.includes(r))) {
      next('/403');
    } else {
      next();
    }
  });
  ```

### 2. 按钮级权限
控制页面内具体按钮、选项卡等元素的可见性/可用性。

- **实现方式**：  
  - 封装权限指令（Vue）或高阶组件（React），传入所需权限标识，与用户权限比对，控制元素渲染。  
  - 将用户权限列表存入全局状态（如 Redux、Vuex），在组件中通过条件判断直接使用 `v-if` 或 `&&` 控制显示。  
  - 权限数据通常由后端返回（如按钮权限列表）。  

- **示例（React）**：  
  ```jsx
  // 自定义权限组件
  const AuthButton = ({ permission, children }) => {
    const userPermissions = useSelector(state => state.user.permissions);
    return userPermissions.includes(permission) ? children : null;
  };
  // 使用
  <AuthButton permission="user:add">
    <Button>新增用户</Button>
  </AuthButton>
  ```

### 3. 数据级权限
控制用户能访问哪些具体数据（如某条记录、某个字段）。

- **实现方式**：  
  - 数据级权限主要由**后端负责**，前端仅根据后端返回的数据进行展示。  
  - 前端可在请求时携带用户信息，后端根据用户角色/权限过滤数据（如只返回所属部门的数据）。  
  - 某些场景下，前端需根据权限调整展示逻辑，例如隐藏某些敏感字段或禁用操作按钮，这需要后端在返回数据时同时提供权限元信息（如 `editable: true`）。  

- **示例**：  
  ```jsx
  // 后端返回数据包含权限标识
  const data = await fetch('/api/records');
  // data.permissions 如 { canEdit: true, canDelete: false }
  <Table>
    {data.records.map(record => (
      <tr key={record.id}>
        <td>{record.name}</td>
        <td>
          {data.permissions.canEdit && <Button>编辑</Button>}
          {data.permissions.canDelete && <Button>删除</Button>}
        </td>
      </tr>
    ))}
  </Table>
  ```

### 总结
- **前端权限管理**的核心是**根据用户权限动态控制视图层**，但数据安全必须依赖后端校验。  
- 权限数据通常在登录后由后端返回（如角色列表、权限点），前端存储并配合路由守卫、指令等实现统一控制。  
- 对于复杂权限模型（如 ABAC），前端需与后端协商权限数据结构，并设计灵活的权限判断函数。

### 图表库选择

```javascript
  // 释放视频资源
  releaseVideoInstance(videoId, options = {}) {
    const videoData = this.videoPool.get(videoId);
    if (!videoData) return;
    
    const { instance } = videoData;
    
    // 1. 停止播放
    if (!instance.paused) {
      instance.pause();
    }
    
    // 2. 分离媒体源
    if (instance.src) {
      if (options.clearSrc) {
        instance.src = '';
      } else {
        instance.removeAttribute('src');
        instance.load();
      }
    }
    
    // 3. 清除缓冲区
    if (instance.buffered && instance.buffered.length > 0) {
      // 有些浏览器不支持直接清除
      try {
        instance.currentTime = 0;
      } catch (e) {}
    }
    
    // 4. 从DOM中移除（如果已附加）
    if (instance.parentNode) {
      instance.parentNode.removeChild(instance);
    }
    
    // 5. 从池中移除
    this.videoPool.delete(videoId);
    
    // 强制垃圾回收提示（谨慎使用）
    if (options.forceGC && typeof global.gc === 'function') {
      global.gc();
    }
  }
}
```

```javascript
class InteractionManager {
  constructor() {
    this.pendingActions = new Map();
    this.optimisticUpdates = new Map();
    this.syncQueue = new Queue();
    this.retryStrategy = new ExponentialBackoff();
  }
  
  // 点赞功能
  async likeVideo(videoId) {
    const actionId = `${videoId}_like_${Date.now()}`;
    
    // 1. 立即更新UI（乐观更新）
    this.updateUIOptimistically(videoId, 'like', true);
    this.optimisticUpdates.set(actionId, {
      type: 'like',
      videoId,
      timestamp: Date.now(),
      state: 'pending'
    });
    
    // 2. 加入同步队列
    this.syncQueue.enqueue({
      actionId,
      execute: async () => {
        try {
          const response = await api.likeVideo(videoId);
          
          // 更新状态为成功
          this.optimisticUpdates.set(actionId, {
            ...this.optimisticUpdates.get(actionId),
            state: 'success',
            serverResponse: response
          });
          
          return response;
        } catch (error) {
          // 更新状态为失败
          this.optimisticUpdates.set(actionId, {
            ...this.optimisticUpdates.get(actionId),
            state: 'error',
            error
          });
          
          // 回滚UI
          this.rollbackOptimisticUpdate(videoId, 'like');
          
          // 重试逻辑
          await this.retryStrategy.retry(() => this.likeVideo(videoId));
          
          throw error;
        }
      }
    });
    
    // 3. 立即开始同步
    this.processSyncQueue();
  }
  
  // 批量同步
  async processSyncQueue() {
    if (this.isSyncing) return;
    this.isSyncing = true;
    
    try {
      const batchSize = 5;
      const batch = this.syncQueue.dequeue(batchSize);
      
      await Promise.allSettled(batch.map(item => item.execute()));
      
      // 清理成功的操作
      this.cleanupCompletedActions();
      
    } finally {
      this.isSyncing = false;
      
      // 如果队列还有数据，继续处理
      if (this.syncQueue.length > 0) {
        setTimeout(() => this.processSyncQueue(), 100);
      }
    }
  }
}
```

```javascript
class PerformanceMonitor {
  constructor() {

      videoLoadTime: [],
      playbackSuccessRate: 0,

      fps: []
    };

    const loadTime = Date.now() - startTime;
    this.metrics.videoLoadTime.push(loadTime);
    
    if (loadTime > this.thresholds.videoLoadTime) {
      this.reportPerformanceIssue('slow_video_load', {
        videoId,
        loadTime,
        networkType: navigator.connection?.effectiveType
      });
    }
  }
  
  // 内存监控
  monitorMemoryUsage() {
    setInterval(() => {
      if (performance.memory) {
        const usedJSHeapSize = performance.memory.usedJSHeapSize;
        const totalJSHeapSize = performance.memory.totalJSHeapSize;
        const usageRatio = usedJSHeapSize / totalJSHeapSize;
        
        this.metrics.memoryUsage.push(usageRatio);
        
        if (usageRatio > this.thresholds.memoryWarning) {
          // 触发内存清理
          this.triggerMemoryCleanup();
          
          // 上报问题
          this.reportPerformanceIssue('high_memory_usage', {
            usageRatio,
            usedJSHeapSize,
            totalJSHeapSize
          });
        }
      }
    }, 30000); // 每30秒检查一次
  }
}
```

```javascript
class ErrorRecoveryManager {
  constructor() {
    this.errorCounts = new Map();
    this.recoveryStrategies = new Map([
      ['network_error', this.recoverFromNetworkError],
      ['video_decode_error', this.recoverFromDecodeError],
      ['memory_error', this.recoverFromMemoryError]
    ]);
  }
  
  async handleVideoError(videoId, error) {
    const errorType = this.classifyError(error);
    this.errorCounts.set(videoId, (this.errorCounts.get(videoId) || 0) + 1);
    
    // 超过3次错误，放弃并跳过
    if (this.errorCounts.get(videoId) > 3) {
      this.skipProblematicVideo(videoId);
      return;
    }
    
    // 执行恢复策略
    const recoveryStrategy = this.recoveryStrategies.get(errorType);
    if (recoveryStrategy) {
      await recoveryStrategy.call(this, videoId, error);
    } else {
      // 默认恢复：重试一次
      await this.retryVideoLoad(videoId);
    }
  }
  
  async recoverFromNetworkError(videoId, error) {
    // 1. 切换CDN源
    const newUrl = this.selectAlternativeCDN(videoId);
    
    // 2. 降低视频质量
    const lowerQualityUrl = this.getLowerQualityUrl(videoId);
    
    // 3. 尝试重新加载
    await this.retryWithNewSource(videoId, lowerQualityUrl || newUrl);
  }
}
```

### 1. **核心优化点**
- **虚拟列表**：只渲染可见区域+缓冲区
