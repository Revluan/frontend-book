1. 解释JavaScript的事件循环机制，宏任务和微任务的执行顺序是怎样的？请举例说明。
JavaScript 的事件循环（Event Loop）是用于处理异步操作的机制，它基于调用栈、任务队列和微任务队列协调代码执行。
**执行顺序：**
1. 同步代码执行完毕后，检查微任务队列（如 Promise.then、async/await、MutationObserver）。
2. 清空所有微任务后，执行一个宏任务（如 setTimeout、setInterval、I/O 操作）。
3. 重复以上步骤。
**简单例子：**
```javascript
console.log('1'); // 同步代码

setTimeout(() => {
  console.log('2'); // 宏任务
}, 0);

Promise.resolve().then(() => {
  console.log('3'); // 微任务
});

console.log('4'); // 同步代码

// 输出顺序：1, 4, 3, 2
```
**解释：**
- 先执行同步代码，输出 `1` 和 `4`。
- 同步代码执行完，检查微任务队列，执行 Promise.then，输出 `3`。
- 微任务清空后，执行宏任务（setTimeout），输出 `2`。

## 闭包的原理

闭包（Closure）是指函数能够**记住并访问其词法作用域**，即使函数在其原始作用域之外执行。

**核心原理**：
1. **词法作用域**：函数在定义时就确定了它能访问哪些变量，而不是在执行时
2. **作用域链**：函数内部有一个隐藏的 `[[Scope]]` 属性，保存了对其外层作用域的引用
3. **引用保持**：当内部函数引用了外部函数的变量，这些变量不会被销毁，而是被保留在内存中

**简单示例**：
```javascript
function outer() {
  let count = 0;  // 被闭包"捕获"的变量
  
  return function inner() {
    count++;      // 内部函数访问外部变量
    return count;
  };
}

const counter = outer();
console.log(counter()); // 1
console.log(counter()); // 2 - count变量被保留在内存中
```

# 原型链和继承

## 原型链（Prototype Chain）

**原型链**是 JavaScript 实现继承的核心机制。每个对象都有一个内部属性 `[[Prototype]]`（可通过 `__proto__` 访问），指向其原型对象。当访问对象的属性时，如果对象本身没有该属性，JavaScript 会沿着原型链向上查找。

### 原型链示例：
```javascript
// 构造函数
function Animal(name) {
  this.name = name;
}

// 在原型上添加方法
Animal.prototype.speak = function() {
  console.log(`${this.name} makes a noise.`);
};

// 创建实例
const dog = new Animal('Dog');
dog.speak(); // "Dog makes a noise."

// 原型链查找过程：
// 1. dog 对象本身没有 speak 方法
// 2. 查找 dog.__proto__ (即 Animal.prototype)
// 3. 找到 speak 方法并执行
```

## ES5 构造函数继承

ES5 主要通过以下几种方式实现继承：

### 1. **原型链继承**
```javascript
function Parent(name) {
  this.name = name;
  this.colors = ['red', 'blue'];
}

Parent.prototype.sayName = function() {
  console.log(this.name);
};

function Child(name, age) {
  this.age = age;
}

// 关键：子类原型指向父类实例
Child.prototype = new Parent();

const child1 = new Child('Tom', 10);
child1.sayName(); // undefined (问题：无法向父类传参)

// 缺点：所有子类实例共享引用类型属性
child1.colors.push('green');
const child2 = new Child('Jerry', 12);
console.log(child2.colors); // ['red', 'blue', 'green'] (被污染了)
```

### 2. **借用构造函数继承（经典继承）**
```javascript
function Parent(name) {
  this.name = name;
  this.colors = ['red', 'blue'];
}

function Child(name, age) {
  // 关键：在子类中调用父类构造函数
  Parent.call(this, name); // 继承实例属性
  this.age = age;
}

const child1 = new Child('Tom', 10);
const child2 = new Child('Jerry', 12);

child1.colors.push('green');
console.log(child1.colors); // ['red', 'blue', 'green']
console.log(child2.colors); // ['red', 'blue'] (问题解决了)

// 缺点：无法继承父类原型上的方法
child1.sayName(); // TypeError: child1.sayName is not a function
```

### 3. **组合继承（最常用）**
```javascript
function Parent(name) {
  this.name = name;
  this.colors = ['red', 'blue'];
}

Parent.prototype.sayName = function() {
  console.log(this.name);
};

function Child(name, age) {
  // 1. 继承实例属性
  Parent.call(this, name); // 第二次调用Parent
  this.age = age;
}

// 2. 继承原型方法
Child.prototype = new Parent(); // 第一次调用Parent
Child.prototype.constructor = Child;

const child1 = new Child('Tom', 10);
child1.sayName(); // "Tom"
child1.colors.push('green');

const child2 = new Child('Jerry', 12);
console.log(child2.colors); // ['red', 'blue'] (不受影响)

// 缺点：父类构造函数被调用了两次
```

### 4. **寄生组合式继承（最优解）**
```javascript
function Parent(name) {
  this.name = name;
  this.colors = ['red', 'blue'];
}

Parent.prototype.sayName = function() {
  console.log(this.name);
};

function Child(name, age) {
  Parent.call(this, name); // 只调用一次
  this.age = age;
}

// 关键：使用Object.create创建原型，避免调用父类构造函数
Child.prototype = Object.create(Parent.prototype);
Child.prototype.constructor = Child;

const child = new Child('Tom', 10);
child.sayName(); // "Tom"
```

## ES6 Class 继承

ES6 引入了 `class` 语法糖，让继承更加直观：

```javascript
class Parent {
  constructor(name) {
    this.name = name;
    this.colors = ['red', 'blue'];
  }
  
  sayName() {
    console.log(this.name);
  }
  
  // 静态方法
  static staticMethod() {
    console.log('Parent static method');
  }
}

class Child extends Parent {
  constructor(name, age) {
    super(name); // 必须先调用super()
    this.age = age;
  }
  
  // 重写父类方法
  sayName() {
    super.sayName(); // 调用父类方法
    console.log(`Age: ${this.age}`);
  }
  
  // 子类自己的方法
  sayAge() {
    console.log(this.age);
  }
}

const child = new Child('Tom', 10);
child.sayName(); // "Tom" \n "Age: 10"
child.colors.push('green');

Parent.staticMethod(); // "Parent static method"
Child.staticMethod(); // 继承静态方法
```

## ES6 Class 与 ES5 构造函数继承的区别

| 特性 | ES5 构造函数继承 | ES6 Class |
|------|----------------|-----------|
| **语法** | 函数 + 原型 | class、extends、super 关键字 |
| **构造函数** | 普通函数 | constructor 方法 |
| **方法定义** | 在原型上定义：`Parent.prototype.method = function(){}` | 在类中直接定义：`method(){}` |
| **继承实现** | 手动设置原型链：`Child.prototype = Object.create(Parent.prototype)` | extends 关键字自动处理 |
| **调用父类构造函数** | `Parent.call(this, args)` | `super(args)` |
| **调用父类方法** | `Parent.prototype.method.call(this)` | `super.method()` |
| **静态方法继承** | 需手动设置：`Child.__proto__ = Parent` | 自动继承 |
| **类提升** | 函数会提升 | class 不会提升（有暂时性死区） |
| **new 调用** | 可不用 new（不安全） | 必须用 new，否则报错 |
| **原型方法枚举性** | 可枚举（默认） | 不可枚举 |
| **私有字段** | 无内置支持（约定用 _ 开头） | 有私有字段语法：`#privateField` |
| **super 关键字** | 无 | 有，用于调用父类方法 |

### 内部实现差异示例：

**ES5 继承底层实现**：
```javascript
// ES6 class 继承编译为 ES5 后的近似代码
class Parent {}
class Child extends Parent {}

// 相当于：
function Parent() {}
function Child() {
  Parent.call(this);
}

// 设置原型链
Object.setPrototypeOf(Child, Parent); // 继承静态属性
Child.prototype = Object.create(Parent.prototype);
Child.prototype.constructor = Child;
```

**ES6 Class 的特性**：
```javascript
class Animal {
  constructor(name) {
    this.name = name;
  }
  
  // 实例方法（在原型上）
  speak() {
    console.log(`${this.name} makes a noise.`);
  }
  
  // 静态方法
  static isAnimal(obj) {
    return obj instanceof Animal;
  }
  
  // Getter/Setter
  get fullName() {
    return `Animal: ${this.name}`;
  }
  
  set fullName(value) {
    this.name = value.replace('Animal: ', '');
  }
  
  // 私有字段（ES2022）
  #privateField = 'secret';
  
  getSecret() {
    return this.#privateField;
  }
}

class Dog extends Animal {
  constructor(name, breed) {
    super(name); // 必须调用 super
    this.breed = breed;
  }
  
  // 重写方法
  speak() {
    super.speak(); // 调用父类方法
    console.log(`${this.name} barks.`);
  }
  
  // 子类静态方法
  static isDog(obj) {
    return obj instanceof Dog;
  }
}

const dog = new Dog('Buddy', 'Golden Retriever');
dog.speak();
// "Buddy makes a noise."
// "Buddy barks."
```

### 重要注意事项：

1. **super 的使用**：
   ```javascript
   class Child extends Parent {
     constructor() {
       // 在 ES6 中，必须先调用 super() 才能使用 this
       // super() 相当于 Parent.call(this)
       super();
       this.childProp = 'value';
     }
   }
   ```

2. **new.target**：
   ```javascript

     constructor() {

   }
   
   class Child extends Parent {
     constructor() {
       super();
     }
   }

   ```

3. **不能直接调用类**：
   ```javascript
   class Foo {}
   Foo(); // TypeError: Class constructor Foo cannot be invoked without 'new'
   
   function Bar() {}
   Bar(); // 可以调用，但 this 指向全局对象（非严格模式）
   ```

4. **类表达式**：
   ```javascript
   // 类表达式
   const MyClass = class {
     // ...
   };
   
   // 具名类表达式
   const MyClass = class InnerClass {

     }
   };
   ```

## 总结

ES6 的 `class` 语法是 ES5 原型继承的语法糖，提供了更清晰、更安全的面向对象编程方式。它并没有改变 JavaScript 基于原型的本质，但通过更严格的语法规则（如必须使用 `new`、必须先调用 `super()` 等）减少了常见错误。对于现代 JavaScript 开发，推荐使用 `class` 语法，因为它更易读、易维护，并且能更好地配合 TypeScript 等工具。

5. 什么是函数柯里化？请实现一个通用的curry函数，并说明它的应用场景。
# 函数柯里化（Currying）

函数柯里化（Currying）是一种将**多参数函数**转换为**一系列单参数函数**的技术。它得名于数学家 Haskell Curry。

## 核心概念

柯里化的本质是：`f(a, b, c)` → `f(a)(b)(c)`

**简单示例**：
```javascript
// 普通函数
function add(a, b, c) {
  return a + b + c;
}

// 柯里化版本
function curriedAdd(a) {
  return function(b) {
    return function(c) {
      return a + b + c;
    };
  };
}

console.log(add(1, 2, 3));        // 6
console.log(curriedAdd(1)(2)(3)); // 6
```

## 实现通用的 curry 函数

### 版本1：基础实现（固定参数数量）
```javascript
function curry(fn) {
  return function curried(...args) {
    // 如果传入的参数数量 >= 原函数需要的参数数量，直接执行
    if (args.length >= fn.length) {
      return fn.apply(this, args);
    }
    
    // 否则，返回一个新函数接收剩余参数
    return function(...args2) {
      return curried.apply(this, args.concat(args2));
    };
  };
}

// 测试
function sum(a, b, c) {
  return a + b + c;
}

const curriedSum = curry(sum);

console.log(curriedSum(1, 2, 3));      // 6
console.log(curriedSum(1)(2, 3));      // 6
console.log(curriedSum(1)(2)(3));      // 6
console.log(curriedSum(1, 2)(3));      // 6
```

### 版本2：增强版（支持占位符）
```javascript
function curry(fn, placeholder = '_') {
  return function curried(...args) {
    // 过滤占位符，获取有效参数
    const actualArgs = args.slice(0, fn.length);
    const hasPlaceholder = actualArgs.includes(placeholder);
    
    // 如果参数足够且没有占位符，直接执行
    if (actualArgs.length >= fn.length && !hasPlaceholder) {
      return fn.apply(this, actualArgs);
    }
    
    // 否则返回新函数
    return function(...args2) {
      const mergedArgs = [];
      let argsIndex = 0;
      let args2Index = 0;
      
      // 合并参数，用新参数替换占位符
      while (mergedArgs.length < fn.length && 
             (argsIndex < args.length || args2Index < args2.length)) {
        if (argsIndex < args.length) {
          const arg = args[argsIndex++];
          if (arg === placeholder && args2Index < args2.length) {
            mergedArgs.push(args2[args2Index++]);
          } else {
            mergedArgs.push(arg);
          }
        } else {
          mergedArgs.push(args2[args2Index++]);
        }
      }
      
      return curried.apply(this, mergedArgs);
    };
  };
}

// 测试占位符功能
function multiply(a, b, c, d) {
  return a * b * c * d;
}

const curriedMultiply = curry(multiply);
const _ = curry.placeholder || '_';

console.log(curriedMultiply(2, 3, 4, 5));           // 120
console.log(curriedMultiply(_, 3, 4, 5)(2));        // 120
console.log(curriedMultiply(_, _, 4, 5)(2, 3));     // 120
console.log(curriedMultiply(_, 3, _, 5)(2, 4));     // 120
```

### 版本3：自动柯里化（任意数量参数）
```javascript
// 无限柯里化：直到没有参数传入为止
function infiniteCurry(fn) {
  return function curried(...args) {
    if (args.length === 0) {
      // 没有参数时，执行计算
      return fn.call(this);
    }
    
    return function(...args2) {
      if (args2.length === 0) {
        // 收集完所有参数，执行计算
        return fn.apply(this, args);
      }
      // 继续收集参数
      return curried.apply(this, args.concat(args2));
    };
  };
}

// 测试无限柯里化
const addAll = infiniteCurry(function(...args) {
  return args.reduce((sum, num) => sum + num, 0);
});

console.log(addAll(1)(2)(3)());      // 6
console.log(addAll(1, 2)(3, 4)());   // 10
console.log(addAll(1)(2)(3)(4)());   // 10
```

# JavaScript 中的深拷贝与浅拷贝

## 区别

| 特性 | 浅拷贝 | 深拷贝 |
|------|--------|--------|
| **复制深度** | 只复制第一层属性 | 递归复制所有层级 |
| **引用类型处理** | 复制引用（共享内存地址） | 创建全新的对象（独立内存） |
| **修改影响** | 修改嵌套对象会影响原对象 | 修改任何属性都不影响原对象 |
| **性能** | 较快 | 较慢（需要递归遍历） |
| **内存占用** | 较少 | 较多 |

### 示例说明
```javascript

  address: { city: 'New York', zip: '10001' }

// 深拷贝
```

## 完整的深拷贝函数实现

```javascript
function deepClone(target, map = new WeakMap()) {
  // 1. 处理基本数据类型和函数
  if (target === null || typeof target !== 'object') {
    return target;
  }

  // 2. 处理函数（直接返回，函数一般不需要深拷贝）
  if (typeof target === 'function') {
    return target;
  }

  // 3. 处理循环引用
  if (map.has(target)) {
    return map.get(target);
  }

  // 4. 处理 Date 对象
  if (target instanceof Date) {
    return new Date(target.getTime());
  }

  // 5. 处理 RegExp 对象
  if (target instanceof RegExp) {
    return new RegExp(target.source, target.flags);
  }

  // 6. 处理 Map
  if (target instanceof Map) {
    const clonedMap = new Map();
    map.set(target, clonedMap);
    target.forEach((value, key) => {
      clonedMap.set(deepClone(key, map), deepClone(value, map));
    });
    return clonedMap;
  }

  // 7. 处理 Set
  if (target instanceof Set) {
    const clonedSet = new Set();
    map.set(target, clonedSet);
    target.forEach(value => {
      clonedSet.add(deepClone(value, map));
    });
    return clonedSet;
  }

  // 8. 处理 ArrayBuffer
  if (target instanceof ArrayBuffer) {
    return target.slice(0);
  }

  // 9. 处理 TypedArray
  if (ArrayBuffer.isView(target)) {
    return target.slice();
  }

  // 10. 处理普通对象和数组
  const cloneTarget = Array.isArray(target) ? [] : {};
  
  // 保存到映射表，防止循环引用
  map.set(target, cloneTarget);

  // 11. 获取所有属性（包括Symbol属性和不可枚举属性）
  const allKeys = [
    ...Object.keys(target),
    ...Object.getOwnPropertySymbols(target)
  ];

  // 12. 递归拷贝所有属性
  for (const key of allKeys) {
    // 处理属性描述符
    const descriptor = Object.getOwnPropertyDescriptor(target, key);
    
    if (descriptor) {
      // 如果是访问器属性
      if (descriptor.get || descriptor.set) {
        Object.defineProperty(cloneTarget, key, descriptor);
      } else {
        // 如果是数据属性
        cloneTarget[key] = deepClone(target[key], map);
      }
    }
  }

  // 13. 保持原型链
  if (Object.getPrototypeOf(target)) {
    Object.setPrototypeOf(cloneTarget, Object.getPrototypeOf(target));
  }

  return cloneTarget;
}

function simpleDeepClone(obj) {
  // 处理基本类型和 null
  if (obj === null || typeof obj !== 'object') return obj;
  
  // 处理特殊对象类型
  if (obj instanceof Date) return new Date(obj);
  if (obj instanceof RegExp) return new RegExp(obj);
  if (obj instanceof Map) return new Map(Array.from(obj, ([k, v]) => [simpleDeepClone(k), simpleDeepClone(v)]));
  if (obj instanceof Set) return new Set(Array.from(obj, v => simpleDeepClone(v)));
  
  // 处理数组和对象
  const clone = Array.isArray(obj) ? [] : {};
  
  for (const key in obj) {
    if (obj.hasOwnProperty(key)) {
      clone[key] = simpleDeepClone(obj[key]);
    }
  }
  
  return clone;
}

  if (typeof structuredClone === 'function') {
    return structuredClone(target);
  }
```

4. **原型链保持**：使用 `Object.setPrototypeOf()` 保持原型

7. React的Fiber架构是什么？它解决了什么问题？
# React Fiber 架构

## 什么是 Fiber 架构？

**Fiber 是 React 16+ 的新的协调引擎（reconciliation engine）**，它重新实现了虚拟DOM的diff算法，将渲染工作拆分成可中断、可恢复的微任务单元。

### 核心概念：
- **Fiber Node**：每个React元素对应一个Fiber节点，包含组件信息、状态、DOM引用等
- **Work Loop**：工作循环，将渲染任务拆分成小片段
- **双缓冲技术**：维护两棵Fiber树（current和workInProgress）进行交替更新

## Fiber 架构解决的问题

### 1. **解决大型应用卡顿问题（同步渲染阻塞）**
**问题**：React 15 使用递归遍历虚拟DOM，一旦开始渲染就不能中断，导致主线程被长时间占用。

**Fiber解决方案**：
```javascript
// 之前的递归渲染（不可中断）
function render(element) {
  // 深度优先遍历，一次性完成
  element.children.forEach(child => render(child));
}

// Fiber的增量渲染（可中断）
function workLoop(deadline) {
  while (nextUnitOfWork && deadline.timeRemaining() > 1) {
    nextUnitOfWork = performUnitOfWork(nextUnitOfWork);
  }
  // 如果还有任务，下次空闲时继续
  requestIdleCallback(workLoop);
}
```

### 2. **实现任务优先级调度**
**问题**：所有更新同等对待，用户交互可能被批量更新阻塞。

**Fiber解决方案**：
```javascript
// 5种优先级（从高到低）：
1. Immediate - 同步任务，需要立即执行
2. UserBlocking - 用户交互（点击、输入）
3. Normal - 普通更新（默认）
4. Low - 数据获取、分析上报
5. Idle - 空闲时执行

// 示例：高优先级更新可中断低优先级更新
用户输入 → 中断正在进行的渲染 → 立即响应用户 → 继续之前的渲染
```

### 3. **支持并发模式（Concurrent Mode）**
**问题**：同步渲染时，复杂组件树会阻塞主线程。

**Fiber解决方案**：
```javascript
// 开启并发模式
ReactDOM.createRoot(rootNode).render(<App />);

// 并发特性：
- Suspense：数据加载时显示fallback UI
- useTransition：非阻塞状态更新
- useDeferredValue：延迟更新非关键内容
```

### 4. **更好的错误处理**
**问题**：一个组件错误导致整个应用崩溃。

**Fiber解决方案**：
```jsx
// 错误边界（Error Boundaries）
class ErrorBoundary extends React.Component {
  componentDidCatch(error, errorInfo) {
    // Fiber可以捕获渲染过程中的错误
    logErrorToService(error, errorInfo);
  }
  
  render() {
    return this.props.children;
  }
}

// 使用
<ErrorBoundary>
  <BuggyComponent />
</ErrorBoundary>
```

## Fiber 工作流程

```javascript
// 简化的Fiber工作流程
1. 接收更新（setState、useState等）
2. 标记更新优先级
3. 调度器安排任务
4. 开始渲染阶段（可中断）：
   - 创建workInProgress树
   - 执行reconciliation（diff算法）
   - 标记副作用（增删改）
5. 提交阶段（不可中断）：
   - 应用DOM变更
   - 执行生命周期/useEffect
6. 切换current和workInProgress树
```

## 总结

**Fiber 架构解决的核心问题**：
1. **渲染阻塞** → 可中断的增量渲染
2. **无优先级调度** → 基于优先级的任务调度
3. **同步更新** → 支持并发更新
4. **错误传播** → 细粒度的错误边界

**带来的好处**：
- 大型应用保持60fps流畅
- 用户交互立即响应
- 更复杂交互模式（悬停、滚动、手势）
- 更好的数据获取体验（Suspense）

Fiber 不仅是性能优化，更是为 React 未来特性（并发模式、服务器组件等）奠定了基础，使 React 能够适应更复杂的应用场景。

8. useState和useReducer的使用场景有什么区别？在什么情况下应该选择useReducer？
# useState vs useReducer

## 核心区别

| 特性 | useState | useReducer |
|------|----------|------------|
| **适用场景** | 简单状态逻辑 | 复杂状态逻辑 |
| **状态类型** | 单个值或简单对象 | 复杂对象或状态集合 |
| **更新逻辑** | 直接设置值 | 通过action描述更新 |
| **可预测性** | 较低（直接修改） | 高（纯函数更新） |

| **代码组织** | 状态和更新逻辑混在一起 | 状态、action、reducer分离 |

## 实际项目决策指南

### **选择 useState 当：**
1. 状态是简单值（字符串、数字、布尔值）
2. 状态更新逻辑简单（直接设置值）
3. 状态之间没有复杂的依赖关系
4. 不需要维护状态变更历史

### **选择 useReducer 当：**
1. **状态结构复杂**：嵌套对象、数组等
2. **多个状态相互关联**：一个状态变更影响其他状态
3. **有复杂的状态转换逻辑**：需要根据条件进行不同更新
4. **需要维护状态历史**：撤销/重做功能
5. **状态逻辑需要复用**：多个组件使用相同的状态逻辑
6. **需要更好的可测试性**：状态逻辑与UI分离
7. **性能优化需求**：避免不必要的重渲染

## 总结

**什么时候应该使用 useReducer？**

1. **状态结构复杂**：当你的状态是一个包含多个子值的对象时
2. **状态更新逻辑复杂**：下一个状态依赖于前一个状态，或者有多个条件分支
3. **需要操作类型化**：使用action.type明确描述发生了什么
4. **需要可预测的状态更新**：reducer是纯函数，相同的输入总是得到相同的输出
5. **需要时间旅行调试**：记录action历史可以回放状态变化
6. **状态逻辑需要复用或测试**：reducer可以提取到组件外部

**简单规则：**
- 如果你发现自己写了多个`useState`来管理同一个事物的不同方面，考虑`useReducer`
- 如果你的状态更新逻辑包含多个`if-else`或`switch`语句，使用`useReducer`
- 如果你需要从一个事件触发多个状态更新，`useReducer`能更好组织代码

**个人经验法则**：当状态更新逻辑超过3-4行代码，或者一个操作需要更新2个以上的状态时，就该考虑使用`useReducer`了。

# React Reconciliation（协调）算法原理

## 一、核心原理

### 1. **虚拟DOM（Virtual DOM）**
```javascript
// React元素（虚拟DOM节点）
const element = {
  type: 'div',
  props: {
    className: 'container',
    children: [
      { type: 'h1', props: { children: 'Hello' } },
      { type: 'p', props: { children: 'World' } }
    ]
  }
};
```

### 2. **协调过程**
```javascript
// 简化的协调流程
function reconcile(oldVNode, newVNode, container) {
  // 1. 比较两个虚拟DOM节点
  if (oldVNode.type !== newVNode.type) {
    // 类型不同：完全替换
    replaceNode(oldVNode, newVNode, container);
  } else {
    // 类型相同：更新属性
    updateNode(oldVNode, newVNode, container);
    
    // 2. 递归比较子节点
    reconcileChildren(oldVNode.props.children, newVNode.props.children, container);
  }
}
```

### 3. **Diffing 算法**
React 的 Diff 算法基于两个**核心假设**：
1. **类型不同的元素会产生不同的树**：如果元素类型不同，React 会直接重建整棵子树
2. **使用 key 来标识稳定的子元素**：key 帮助 React 识别哪些元素发生了变化

## 二、详细协调过程

### 1. **元素类型比较**
```javascript
// 情况1：类型不同 - 完全重建
// 旧：<div><Counter /></div>
// 新：<span><Counter /></span>

// React会：
1. 卸载整个div及其子组件Counter
2. 卸载Counter组件的所有生命周期（componentWillUnmount）
3. 创建span元素
4. 创建新的Counter实例
5. 执行Counter的constructor、componentDidMount等

// 情况2：类型相同 - 更新属性
// 旧：<div className="old" title="hello" />
// 新：<div className="new" title="world" />

// React会：
1. 保留同一个DOM节点
2. 更新className和title属性
```

### 2. **子节点协调算法**
React 使用**启发式算法**来比较子节点列表，时间复杂度 O(n)：

```javascript
// 传统的diff算法需要O(n³)复杂度
// React通过以下策略优化到O(n)：

// 策略1：同级比较（Tree Diff）
// React不会跨层级移动节点，而是：
// 旧：层级A → 层级B
// 新：层级A → 层级C
// React会：删除B，创建C，而不是移动B到C

// 策略2：列表比较（List Diff）
// 当比较两个子节点列表时：
function reconcileChildrenArray(oldChildren, newChildren, container) {
  // 使用key来匹配新旧节点
  const oldKeyIndexMap = {};
  oldChildren.forEach((child, index) => {
    const key = child.key || index.toString();
    oldKeyIndexMap[key] = index;
  });
  
  // 遍历新子节点
  newChildren.forEach((newChild, newIndex) => {
    const key = newChild.key || newIndex.toString();
    const oldIndex = oldKeyIndexMap[key];
    
    if (oldIndex !== undefined) {
      // 找到匹配的旧节点，递归协调
      reconcile(oldChildren[oldIndex], newChild, container);
      delete oldKeyIndexMap[key]; // 标记为已处理
    } else {
      // 新节点，插入
      mount(newChild, container);
    }
  });
  
  // 删除未匹配的旧节点
  Object.values(oldKeyIndexMap).forEach(oldIndex => {
    unmount(oldChildren[oldIndex]);
  });
}
```

## 三、key 的作用

### 1. **没有 key 的情况（默认使用 index）**
```jsx

  <li>{item}</li>
  // React内部：key = "0", "1", "2"

  <li>{item}</li>

// React的diff过程：
1. 比较 key="0": <li>A</li> → <li>D</li>  // 更新内容：A → D
2. 比较 key="1": <li>B</li> → <li>A</li>  // 更新内容：B → A
3. 比较 key="2": <li>C</li> → <li>B</li>  // 更新内容：C → B
```

# React 合成事件系统
## 什么是合成事件？
**合成事件（SyntheticEvent）** 是 React 包装浏览器原生事件对象的跨浏览器包装器。它提供了与原生事件相同的接口，但在所有浏览器中行为一致。

```javascript
// React 中的事件处理
<button onClick={(e) => {
  // e 是 SyntheticEvent 对象，不是原生 Event
  console.log(e.nativeEvent); // 访问底层原生事件
}}>点击</button>
```

## 合成事件 vs 原生事件
| 特性 | React 合成事件 | 原生 DOM 事件 |
|------|---------------|--------------|
| **命名** | 驼峰命名（onClick） | 全小写（onclick） |
| **事件绑定** | JSX 中直接绑定 | addEventListener |
| **事件对象** | SyntheticEvent（包装对象） | 原生 Event 对象 |
| **跨浏览器** | 完全一致 | 浏览器间有差异 |
| **事件委托** | 自动在根节点委托 | 需手动实现 |
| **事件池** | 17 之前有事件池复用 | 无事件池 |
| **阻止冒泡** | `e.stopPropagation()` | 同上，但行为可能不同 |
| **默认行为** | `e.preventDefault()` | 同上 |
| **性能** | 事件委托减少内存占用 | 每个元素单独绑定 |

### 关键区别示例：
```javascript
// 原生事件
element.addEventListener('click', (e) => {
  console.log(e.target);      // 触发元素
  console.log(e.currentTarget); // 绑定元素（与target相同）
});

// React 合成事件
<button onClick={(e) => {
  console.log(e.target);      // 实际点击的DOM元素
  console.log(e.currentTarget); // React处理的当前元素
  console.log(e.nativeEvent); // 底层原生事件
```

## React 事件委托的实现

### 1. **事件委托架构**
React 17 之前和之后有所不同：

**React 16 及之前：**
```javascript
// 所有事件都委托到 document
document.addEventListener('click', dispatchEvent);
document.addEventListener('change', dispatchEvent);
// ... 所有其他事件
```

**React 17+：**
```javascript
// 事件委托到 React 根容器
const rootNode = document.getElementById('root');
rootNode.addEventListener('click', dispatchEvent);
rootNode.addEventListener('change', dispatchEvent);
```

### 2. **实现原理**

```javascript
// 简化的 React 事件委托实现
class ReactEventSystem {
  constructor(rootElement) {
    this.root = rootElement;
    this.eventMap = new Map(); // 存储事件处理器
    this.setupEventDelegation();
  }

  // 1. 在根节点绑定原生事件
  setupEventDelegation() {
    // 绑定支持的所有事件类型
    const eventTypes = ['click', 'change', 'input', 'keydown', 'submit'];
    
    eventTypes.forEach(eventType => {
      this.root.addEventListener(eventType, (nativeEvent) => {
        this.handleEvent(nativeEvent);
      }, true); // 捕获阶段
    });
  }

  // 2. 事件分发
  handleEvent(nativeEvent) {
    // 创建合成事件
    const syntheticEvent = this.createSyntheticEvent(nativeEvent);
    
    // 模拟事件传播路径（冒泡）
    const path = this.getEventPath(nativeEvent);
    
    // 捕获阶段
    for (let i = path.length - 1; i >= 0; i--) {
      const node = path[i];
      const captureHandler = this.getEventHandler(node, nativeEvent.type, true);
      if (captureHandler) {
        captureHandler(syntheticEvent);
        if (syntheticEvent.isPropagationStopped) break;
      }
    }
    
    // 目标阶段（如果冒泡没有被阻止）
    if (!syntheticEvent.isPropagationStopped) {
      const target = nativeEvent.target;
      const targetHandler = this.getEventHandler(target, nativeEvent.type, false);
      if (targetHandler) targetHandler(syntheticEvent);
    }
    
    // 冒泡阶段
    if (!syntheticEvent.isPropagationStopped) {
      for (let i = 0; i < path.length; i++) {
        const node = path[i];
        const bubbleHandler = this.getEventHandler(node, nativeEvent.type, false);
        if (bubbleHandler) {
          bubbleHandler(syntheticEvent);
          if (syntheticEvent.isPropagationStopped) break;
        }
      }
    }
  }

  // 3. 创建合成事件
  createSyntheticEvent(nativeEvent) {
    return {
      nativeEvent,
      type: nativeEvent.type,
      target: nativeEvent.target,
      currentTarget: null,
      stopPropagation() {
        this.isPropagationStopped = true;
        nativeEvent.stopPropagation();
      },
      preventDefault() {
        nativeEvent.preventDefault();
      },
      isPropagationStopped: false,
      // ... 其他属性和方法
    };
  }

  // 4. 获取事件传播路径
  getEventPath(nativeEvent) {
    const path = [];
    let node = nativeEvent.target;
    
    while (node && node !== this.root) {
      path.push(node);
      node = node.parentNode;
    }
    
    return path;
  }

  // 5. 获取节点的事件处理器
  getEventHandler(node, eventType, isCapture) {
    // 从 React 内部存储中获取
    // 实际 React 使用 Fiber 节点存储事件处理器
    const fiberNode = this.getFiberFromDOM(node);
    if (!fiberNode) return null;
    
    const eventName = `on${eventType}${isCapture ? 'Capture' : ''}`;
    return fiberNode.props[eventName];
  }
}
```

# React 组件渲染性能优化方法
## 1. **React.memo / PureComponent**

### 使用场景：避免不必要的子组件重渲染
```jsx

  return <div>{data.value}</div>;
};

  return <div>{data.value}</div>;
}, (prevProps, nextProps) => {
  // 自定义比较函数（可选）
  return prevProps.data.id === nextProps.data.id;
});

// 类组件版本

    return <div>{this.props.data.value}</div>;
  }
}
```

**最佳实践**：
- 当父组件频繁更新但子组件 props 变化不大时
- 列表项组件，避免一个项更新导致全部重渲染
- 复杂表单的字段组件

## 2. **useMemo / useCallback**

### 使用场景：缓存昂贵的计算结果和函数引用
```jsx

  const filteredItems = items.filter(item => item.type === filter);
  
  // ✅ 只有 items 或 filter 变化时才重新计算
  const filteredItems = useMemo(() => {
    console.log('Filtering items...');
    return items.filter(item => item.type === filter);
  }, [items, filter]); // 依赖数组
  
  // ❌ 每次渲染都创建新函数
  const handleClick = () => { console.log('Clicked'); };
  
  // ✅ 缓存函数引用
  const handleClick = useCallback(() => {
    console.log('Clicked');
  }, []); // 空依赖表示函数不会变化
  
  return <div>{filteredItems.length} items</div>;
};
```

**最佳实践**：
- `useMemo`：计算密集型操作、对象/数组的复杂转换
- `useCallback`：将函数传递给 memoized 子组件、作为 useEffect 的依赖

```jsx
      setData(result);
```

# BFC（块级格式化上下文）
## 什么是 BFC？

**BFC（Block Formatting Context）** 是 Web 页面中一个独立的渲染区域，它决定了块级盒子如何布局，以及与外部元素的关系。

### 核心特性：
- **内部垂直排列**：BFC 内的块级元素从上到下垂直排列
- **外边距不重叠**：BFC 内外的外边距不会合并
- **包含浮动元素**：BFC 会计算内部浮动元素的高度
- **阻止元素被浮动覆盖**：BFC 不会与浮动元素重叠

## 如何触发 BFC？

## BFC 解决的实际问题

### 1. **清除浮动（最常用）**
```html

  .container {
    border: 2px solid #333;
  }
  .float-child {
    float: left;
    width: 100px;
    height: 100px;
    background: #f00;
  }
</style>

<div class="container">
  <div class="float-child"></div>
</div>
<!-- container高度为0，边框塌陷成一条线 -->

<!-- 解决方案：触发BFC -->
<style>
  .container-bfc {
    border: 2px solid #333;
    overflow: hidden; /* 触发BFC */
```

# CSS 优先级计算

## 权重计算规则

CSS 优先级通过 **权重（Specificity）** 计算，权重是一个四位的计数值：

```
[内联样式, ID选择器, 类/伪类/属性选择器, 元素/伪元素选择器]
```

### 权重值对照表

| 选择器类型 | 权重值 | 示例 | 说明 |
|-----------|--------|------|------|
| **内联样式** | `1,0,0,0` | `style="color: red;"` | 权重最高 |
| **ID 选择器** | `0,1,0,0` | `#header` | 每个ID加100 |
| **类选择器** | `0,0,1,0` | `.button` | 每个类加10 |
| **属性选择器** | `0,0,1,0` | `[type="text"]` | 与类同级 |
| **伪类选择器** | `0,0,1,0` | `:hover` | 与类同级 |
| **元素选择器** | `0,0,0,1` | `div` | 每个元素加1 |
| **伪元素选择器** | `0,0,0,1` | `::before` | 与元素同级 |
| **通配符** | `0,0,0,0` | `*` | 权重为0 |
| **继承样式** | **无权重** | 继承父元素样式 | 最低优先级 |

## !important 的特殊性

### 1. **!important 的作用**
```css
/* !important 是最高优先级，超越所有其他规则 */
.button {
  color: blue !important;  /* 最高优先级 */
}

#special.button {
  color: red;  /* 即使权重更高，也无法覆盖!important */
}
```

### 2. **!important 的权重比较**
```css
/* 多个!important比较时，看选择器权重 */

/* 权重：0,1,1,0 */
#header .nav {
  color: red !important;
}

/* 权重：0,0,2,0 */
.nav.active {
  color: blue !important;  /* 这个生效，因为#header .nav权重更高 */
}
```

## 优先级计算示例

### 1. **基础比较**
```css
/* 示例1 */
div { color: black; }              /* 权重：0,0,0,1 = 1 */
.container { color: blue; }        /* 权重：0,0,1,0 = 10（胜出） */

/* 示例2 */
.button.primary { color: red; }    /* 权重：0,0,2,0 = 20 */
#submit { color: green; }          /* 权重：0,1,0,0 = 100（胜出） */

/* 示例3 */
body div a:hover { color: purple; } /* 权重：0,0,1,3 = 13 */
.nav > .link { color: orange; }     /* 权重：0,0,2,0 = 20（胜出） */
```

### 2. **复合选择器计算**
```css
/* 权重计算：分别统计每个级别的数量 */

/* 权重：0,1,1,2 = [0,1,1,2] */
#header ul.nav li {
  color: red;
}

/* 权重：0,0,3,1 = [0,0,3,1] */
body .main .content .title {
  color: blue;  /* 这个生效，因为ID权重更高（第二位的1>0） */
}

/* 虽然 3>1，但比较时先比较第一位，再比较第二位... */
/* 第一位都是0，比较第二位：1 > 0，所以第一个选择器胜出 */
```

### 3. **实际计算过程**
```javascript
// 权重比较算法（伪代码）
function compareSpecificity(selectorA, selectorB) {
  // 权重数组：[内联, ID, 类, 元素]
  const weightA = calculateWeight(selectorA); // 例如：[0,1,2,3]
  const weightB = calculateWeight(selectorB); // 例如：[0,0,5,1]
  
  // 从左到右逐位比较
  for (let i = 0; i < 4; i++) {
    if (weightA[i] > weightB[i]) return 'A wins';
    if (weightA[i] < weightB[i]) return 'B wins';
  }
  
  return '相同权重，后定义的生效';
}

// 示例比较
// A: #header .nav li    → [0,1,1,1]
// B: .nav.nav.nav.nav.nav → [0,0,5,0]
// 比较过程：
// 第一位：0 vs 0 → 平
// 第二位：1 vs 0 → A胜出（ID权重更高）
```

## 特殊情况

### 1. **相同权重：后来者居上**
```css
/* 相同权重时，后定义的样式生效 */
.button {
  color: red;
}

.button {
  color: blue;  /* 这个生效 */
}
```

### 2. **来源重要性排序**
```
!important > 内联样式 > ID选择器 > 类选择器 > 元素选择器 > 通配符 > 继承
```

### 3. **属性选择器和伪类的权重**
```css
/* 属性选择器权重与类相同 */
input[type="text"] { color: red; }  /* 权重：0,0,1,1 */
.input.text { color: blue; }        /* 权重：0,0,2,0（这个更高） */

/* 伪类权重与类相同 */
a:hover { color: red; }            /* 权重：0,0,1,1 */
.link.hover { color: blue; }       /* 权重：0,0,2,0（这个更高） */
```

### 4. **:not() 伪类的特殊性**
```css
/* :not() 本身不计权重，但内部选择器计入 */
div:not(.special) { color: red; }  /* 权重：0,0,1,1（.special计入类权重） */
```

## 权重计算的常见误区

### 误区1：十进制数字比较
```css
/* ❌ 错误理解：把权重当成十进制数字相加 */
#id (100) + .class (10) + div (1) = 111
.class (10) + .class (10) + .class (10) = 30
/* 认为 111 > 30，所以第一个权重高（这是巧合正确，但理解错误） */

/* ✅ 正确理解：四位数组逐位比较 */
#id .class div → [0,1,1,1] (0个内联，1个ID，1个类，1个元素)
.class.class.class → [0,0,3,0] (0个内联，0个ID，3个类，0个元素)
/* 比较：第一位都是0，第二位1>0，所以第一个胜出 */
```

### 误区2：11个类 > 1个ID
```css
/* 11个类选择器 vs 1个ID选择器 */
.class.class.class.class.class.class.class.class.class.class.class {
  color: blue;  /* 权重：[0,0,11,0] */
}

#id {
  color: red;   /* 权重：[0,1,0,0] */
}
/* 结果：ID选择器胜出（因为第二位1>0） */
/* 无论多少个类选择器，权重都比不上一个ID选择器 */
```

### 误区3：内联样式可以被普通选择器覆盖
```html
<!-- 内联样式权重很高 -->
<div id="myDiv" class="box" style="color: red;">Hello</div>

<style>
  #myDiv { color: blue; }      /* 无法覆盖内联样式 */
  .box { color: green; }       /* 无法覆盖内联样式 */
  div { color: yellow; }       /* 无法覆盖内联样式 */
  
  /* 只有!important可以覆盖内联样式 */
  #myDiv { color: black !important; }  /* 这个可以生效 */
</style>
```

```
每个类/属性/伪类    = 0,0,1,0
每个元素/伪元素     = 0,0,0,1
通配符/继承         = 0,0,0,0
```

### **比较规则**
1. **从左到右**逐位比较四个数字
2. 数字大的胜出
3. 所有数字都相同 → 后定义的样式生效
4. `!important` 打破所有规则（除了另一个 `!important`）

### **简单记忆法**
- **!important**：王者，无敌（除非遇到另一个!important王者）
- **内联样式**：皇帝，权重1000
- **ID选择器**：大臣，权重100
- **类选择器**：官员，权重10
- **元素选择器**：平民，权重1

**记住**：权重不是十进制加法，而是**四位数的比较**。一个ID选择器权重永远高于无数个类选择器。

16. 如何实现一个元素的水平垂直居中？请列举至少4种方法，并说明各自的适用场景。

## 一、Flexbox 布局（最推荐）

### 1. **基本用法**
```css
.parent {
  display: flex;
  justify-content: center;  /* 水平居中 */
  align-items: center;      /* 垂直居中 */
```

### 2. **多种变体**
```css

  display: flex;
}

.center-item {
  margin: auto;  /* Flexbox中，margin: auto会让元素在交叉轴和主轴上都居中 */
}

/* 变体2：多个元素居中 */
.parent {
  display: flex;
  flex-direction: column;  /* 垂直排列 */
  justify-content: center;
  align-items: center;
}

/* 变体3：单个元素使用margin auto（在Flex容器中） */
.parent {
  display: flex;
```

# 首屏加载优化
## 一、什么是首屏加载优化？

**首屏加载优化**是指优化用户首次访问页面时，**第一屏可视区域内容**的加载速度和渲染性能，让用户尽快看到可交互的内容。

### 核心指标
- **FCP（First Contentful Paint）**：首次内容绘制
- **LCP（Largest Contentful Paint）**：最大内容绘制（< 2.5秒为良好）
- **TTI（Time to Interactive）**：可交互时间

### 7. **CDN与边缘计算**
```javascript
// 使用Cloudflare Workers进行边缘优化
// worker.js - 在CDN边缘节点优化响应
addEventListener('fetch', event => {
  event.respondWith(handleRequest(event.request));
});

async function handleRequest(request) {
  const url = new URL(request.url);
  
  // 1. 边缘缓存HTML
  if (url.pathname === '/') {
    const cache = caches.default;
    let response = await cache.match(request);
    
    if (!response) {
      response = await fetch(request);
      
      // 克隆响应进行缓存
      const responseToCache = response.clone();
      event.waitUntil(cache.put(request, responseToCache));
    }
    
    return response;
  }
  
  // 2. 优化图片（边缘转换WebP）
  if (url.pathname.endsWith('.jpg') || url.pathname.endsWith('.png')) {
    const accept = request.headers.get('Accept');
    if (accept && accept.includes('image/webp')) {
      // 重写到WebP版本
      url.pathname = url.pathname.replace(/\.(jpg|png)$/, '.webp');
      return fetch(new Request(url, request));
    }
  }
  
  return fetch(request);
}
```

19. 解释重排（reflow）和重绘（repaint）的区别，如何减少重排和重绘？
# 重排（Reflow）和重绘（Repaint）

## 一、核心区别

### **重排（Reflow / Layout）**
```javascript
// 重排：重新计算元素的位置和几何属性
// 触发时机：影响布局的样式改变
const reflowTriggers = [
  '添加/删除DOM元素',
  '元素尺寸变化（width/height/padding/margin）',
  '内容变化（文本、图片大小改变）',
  '字体大小变化',
  '激活CSS伪类（如:hover）',
  '计算offsetWidth、scrollTop等布局属性',
  '窗口大小改变（resize）',
  '设置CSS的display、position、float等'
];
```

### **重绘（Repaint / Paint）**
```javascript
// 重绘：重新绘制元素的视觉样式，不改变布局
// 触发时机：只影响外观的样式改变
const repaintTriggers = [
  '颜色变化（color/background-color）',
  '边框样式（border-style/border-color）',
  '可见性（visibility/opacity）',
  '背景图片（background-image）',
  '文字装饰（text-decoration）',
  '阴影（box-shadow/text-shadow）'
];
```

## 二、性能影响对比

### **渲染管道（Rendering Pipeline）**
```
JavaScript → Style → Layout → Paint → Composite
            ↑        ↑        ↑       ↑
          重绘触发  重排触发  重绘   合成层优化
```

### **性能开销**
```javascript
const performanceCost = {
  // 重排：最高开销（触发完整渲染管道）
  reflow: {
    steps: [
      '1. 重新计算样式（Recalculate Style）',
      '2. 重新布局（Layout/Reflow）',
      '3. 重新绘制（Paint）',
      '4. 合成（Composite）'
    ],
    cost: '非常高，可能影响整个文档'
  },
  
  // 重绘：中等开销（跳过布局阶段）
  repaint: {
    steps: [
      '1. 重新计算样式（Recalculate Style）',
      '2. 重新绘制（Paint）',
      '3. 合成（Composite）'
    ],
    cost: '中等，只影响相关元素'
  },
  
  // 合成层变换：最低开销（跳过布局和绘制）

  }

```

```javascript
class OptimizedInfiniteList {
  constructor() {
    this.items = [];
    this.container = null;
    this.visibleItems = new Set();
    
    // 使用IntersectionObserver监听可见性
    this.observer = new IntersectionObserver(
      this.handleVisibilityChange.bind(this),
      { threshold: 0.1 }
    );
  }
  
  renderItem(item, index) {
    const element = document.createElement('div');
    element.className = 'list-item';
    element.dataset.index = index;
    
    // 使用transform而不是top/left
    element.style.transform = `translateY(${index * 50}px)`;
    
    // 仅渲染可见区域的内容
    if (this.isInViewport(index)) {
      this.renderContent(element, item);
    }
    
    this.observer.observe(element);
    return element;
  }
  
  isInViewport(index) {
    const viewportHeight = window.innerHeight;
    const itemTop = index * 50;
    const itemBottom = itemTop + 50;
    
    return itemBottom > window.scrollY && 
           itemTop < window.scrollY + viewportHeight;
  }
  
  handleVisibilityChange(entries) {
    entries.forEach(entry => {
      const index = parseInt(entry.target.dataset.index);
      
      if (entry.isIntersecting) {
        this.renderContent(entry.target, this.items[index]);
        this.visibleItems.add(index);
      } else {
        this.clearContent(entry.target);
        this.visibleItems.delete(index);
      }
    });
  }
}
```

### 3. **批量样式更新**
```javascript
class StyleBatcher {
  constructor() {
    this.updates = new Map();
    this.batchId = null;
  }
  
  scheduleUpdate(element, styles) {
    if (!this.updates.has(element)) {
      this.updates.set(element, {});
    }
    
    Object.assign(this.updates.get(element), styles);
    
    if (!this.batchId) {
      this.batchId = requestAnimationFrame(() => this.flush());
    }
  }
  
  flush() {
    this.updates.forEach((styles, element) => {
      // 批量应用样式
      Object.assign(element.style, styles);
    });
    
    this.updates.clear();
    this.batchId = null;
  }
}
```

## 一、懒加载的核心原理

### **基本思想**：
延迟加载非可视区域内的图片，当图片进入或即将进入可视区域时，再将真实的图片地址赋给 `src` 属性。

```javascript

  alt="描述"
```

## 二、传统懒加载实现（基于 scroll 事件）

### 1. **基本实现**
```javascript
class TraditionalLazyLoad {
  constructor() {
    this.images = document.querySelectorAll('img[data-src]');
    this.init();
  }
  
  init() {
    // 初始检查
    this.checkImages();
    
    // 监听滚动事件（带节流）
    const scrollHandler = this.throttle(() => {
      this.checkImages();
    }, 100);
    
    window.addEventListener('scroll', scrollHandler);
    window.addEventListener('resize', scrollHandler);
  }
  
  // 节流函数
  throttle(func, delay) {
    let lastCall = 0;
    return function(...args) {
      const now = Date.now();
      if (now - lastCall >= delay) {
        lastCall = now;
        func.apply(this, args);
      }
    };
  }
  
  // 检查图片是否进入视口
  checkImages() {
    const viewportHeight = window.innerHeight;
    const scrollTop = window.pageYOffset || document.documentElement.scrollTop;
    
    this.images.forEach(img => {
      if (img.dataset.loaded) return;
      
      const imgTop = this.getOffsetTop(img);
      
      // 判断图片是否进入视口（提前200px加载）
      if (imgTop < viewportHeight + scrollTop + 200) {
        this.loadImage(img);
      }
    });
  }
  
  // 计算元素到文档顶部的距离
  getOffsetTop(element) {
    let offsetTop = 0;
    while (element) {
      offsetTop += element.offsetTop;
      element = element.offsetParent;
    }
    return offsetTop;
  }
  
  // 加载图片
  loadImage(img) {
    const realSrc = img.dataset.src;
    
    // 创建新的Image对象预加载
    const tempImg = new Image();
    tempImg.onload = () => {
      img.src = realSrc;
      img.dataset.loaded = true;
      img.classList.add('loaded');
    };
    
    tempImg.src = realSrc;
  }
}
```

## 三、IntersectionObserver 实现懒加载

### 1. **基本实现**
```javascript
class ModernLazyLoad {
  constructor(options = {}) {
    this.options = {
      root: null,           // 默认为视口
      rootMargin: '200px',  // 提前200px加载
      threshold: 0.01,      // 至少1%可见
      ...options
    };
    
    this.observer = null;
    this.init();
  }
  
  init() {
    // 创建IntersectionObserver实例
    this.observer = new IntersectionObserver(
      this.handleIntersection.bind(this),
      this.options
    );
    
    // 观察所有需要懒加载的图片
    const images = document.querySelectorAll('img[data-src]');
    images.forEach(img => {
      this.observer.observe(img);
    });
  }
  
  handleIntersection(entries, observer) {
    entries.forEach(entry => {
      if (entry.isIntersecting) {
        const img = entry.target;
        this.loadImage(img);
        observer.unobserve(img); // 加载后停止观察
      }
    });
  }
  
  async loadImage(img) {
    const src = img.dataset.src;
    
    if (!src) return;
    
    try {
      // 添加加载中状态
      img.classList.add('loading');
      
      // 预加载图片
      await this.preloadImage(src);
      
      // 应用真实图片源
      img.src = src;
      img.removeAttribute('data-src');
      
      // 添加加载完成状态
      img.classList.remove('loading');
      img.classList.add('loaded');
      
    } catch (error) {
      console.error('图片加载失败:', src, error);
      img.classList.add('error');
    }
  }
  
  preloadImage(src) {
    return new Promise((resolve, reject) => {
      const image = new Image();
      image.onload = () => resolve(src);
      image.onerror = reject;
      image.src = src;
    });
  }
  
  // 动态添加新的图片
  addImage(imgElement) {
    this.observer.observe(imgElement);
  }
}
```

### 2. **长文章图片懒加载**
```javascript
class ArticleLazyLoad {
  constructor() {
    this.observer = null;
    this.imageQueue = new Set();
    this.currentPriority = 0;
    this.maxConcurrent = 3; // 最多同时加载3张图
    this.loadingCount = 0;
    
    this.init();
  }
  
  init() {
    this.observer = new IntersectionObserver(
      (entries) => {
        entries.forEach(entry => {
          const img = entry.target;
          const priority = this.calculatePriority(entry);
          
          if (entry.isIntersecting) {
            // 加入加载队列
            this.imageQueue.add({ img, priority });
            this.processQueue();
          } else {
            // 移除队列
            this.removeFromQueue(img);
          }
        });
      },
      {
        threshold: this.buildThresholds(100) // 创建100个阈值点
      }
    );
  }
  
  // 计算图片加载优先级（根据可见比例和位置）
  calculatePriority(entry) {
    const viewportHeight = window.innerHeight;
    const rect = entry.boundingClientRect;
    
    // 计算图片中心到视口中心的距离
    const imgCenter = rect.top + rect.height / 2;
    const viewportCenter = viewportHeight / 2;
    const distance = Math.abs(imgCenter - viewportCenter);
    
    // 可见比例越高，优先级越高
    const ratioScore = entry.intersectionRatio * 100;
    
    // 距离视口中心越近，优先级越高
    const distanceScore = Math.max(0, 100 - (distance / viewportHeight * 100));
    
    return (ratioScore + distanceScore) / 2;
  }
  
  // 处理加载队列
  processQueue() {
    if (this.loadingCount >= this.maxConcurrent || this.imageQueue.size === 0) {
      return;
    }
    
    // 按优先级排序
    const sortedQueue = Array.from(this.imageQueue).sort((a, b) => b.priority - a.priority);
    
    sortedQueue.slice(0, this.maxConcurrent - this.loadingCount).forEach(item => {
      this.loadImage(item.img);
      this.imageQueue.delete(item);
    });
  }
  
  // 构建阈值数组
  buildThresholds(steps) {
    const thresholds = [];
    for (let i = 0; i <= steps; i++) {
      thresholds.push(i / steps);
    }
    return thresholds;
  }
}
```

```javascript
class UltimateLazyLoad {
  constructor() {
    // 检测浏览器是否支持loading="lazy"
    if ('loading' in HTMLImageElement.prototype) {
      this.useNativeLazyLoad();
    } else if ('IntersectionObserver' in window) {
      this.useIntersectionObserver();
    } else {
      this.useTraditional();
    }
  }
  
  useNativeLazyLoad() {
    // 将data-src转换为src，添加loading="lazy"
    document.querySelectorAll('img[data-src]').forEach(img => {
      img.src = img.dataset.src;
      img.loading = 'lazy';
      img.removeAttribute('data-src');
    });
  }
  
  useIntersectionObserver() {
    // IntersectionObserver实现
    const observer = new IntersectionObserver((entries) => {
      entries.forEach(entry => {
        if (entry.isIntersecting) {
          const img = entry.target;
          img.src = img.dataset.src;
          observer.unobserve(img);
        }
      });
    });
    
    document.querySelectorAll('img[data-src]').forEach(img => {
      observer.observe(img);
    });
  }
}
```

## 二、Tree Shaking原理

### 1. **基本原理**
```javascript
// Tree Shaking = "摇树" = 摇掉树上枯死的叶子（未使用的代码）

// 原始代码
// math.js
export function square(x) {
  console.log('square');
  return x * x;
}

export function cube(x) {
  console.log('cube');
  return x * x * x;
}

// main.js
import { square } from './math.js';
console.log(square(2));

// 经过Tree Shaking后，打包结果：
// cube函数被移除（dead code elimination）

  function square(x) {
    console.log('square');
    return x * x;
  }
  console.log(square(2));
})();
```

```javascript
  constructor() {
    this.usedExports = new Set();

  collectUsedExports(module) {
    // 分析模块中的import语句
    module.dependencies.forEach(dep => {
      if (dep.type === 'import') {
        // 记录哪些export被使用了
        this.usedExports.add(`${dep.moduleId}:${dep.exportName}`);
      }
    });

  markUnusedExports(allModules) {
    allModules.forEach(module => {
      module.exports.forEach(exportName => {
        const key = `${module.id}:${exportName}`;
        if (!this.usedExports.has(key)) {
          module.markExportAsUnused(exportName);
        }
      });
    });
  }
```

## 二、Vite 的核心原理

### 1. **基于原生 ES Modules（革命性设计）**
```javascript
// 传统打包工具（Webpack等）思路
// 1. 打包所有模块成bundle
// 2. 浏览器加载一个或多个大文件

// Vite 思路
// 1. 不打包，直接在浏览器中运行ESM
// 2. 浏览器按需请求模块

// 实际请求示例
// index.html
<script type="module">
  import { createApp } from 'vue'  // 会被转换为绝对路径
  import App from './App.vue'      // .vue文件会被即时编译

// 浏览器实际请求
GET /node_modules/.vite/vue.js?v=xxx
GET /src/App.vue?import&type=template
GET /src/App.vue?import&type=script
```

### 3. **按需编译（核心优势）**
```javascript
// 对比：Webpack vs Vite 的编译时机
const compilationTiming = {
  'Webpack（全量编译）': {

    '问题': '项目越大，等待时间越长'
  },
  
  'Vite（按需编译）': {
    '时机': '浏览器请求时 + 文件修改时',
    '范围': '仅请求的文件',
    '优势': '编译量最小化，响应最快'
  }
};

// Vite 的请求处理流程
class ViteServer {
  async handleRequest(request) {
    const url = request.url;
    
    // 1. 静态文件（直接返回）
    if (url.endsWith('.js') || url.endsWith('.css')) {
      return serveStaticFile(url);
    }
    
    // 2. Vue/React 单文件组件（即时编译）
    if (url.endsWith('.vue') || url.endsWith('.jsx')) {
      const source = await readFile(url);
      const compiled = await compileSFC(source); // 只编译这个文件
      return compiled;
    }
    
    // 3. TypeScript 文件（即时转译）
    if (url.endsWith('.ts')) {
      const source = await readFile(url);
      const js = esbuild.transform(source, { loader: 'ts' });
      return js;
    }
  }
}
```

### 5. **创新的 HMR 实现**
```javascript
// Vite HMR 比传统HMR更精确
class ViteHMR {
  constructor() {
    // 1. 监听文件变化
    chokidar.watch('src/**/*').on('change', (file) => {
      this.handleFileChange(file);
    });
  }
  
  handleFileChange(file) {
    // 2. 找到受影响模块（精确到导入链）
    const affectedModules = this.getAffectedModules(file);
    
    // 3. 仅重新编译这些模块
    const updates = affectedModules.map(module => {
      const newCode = compileModule(module);
      return { id: module.id, newCode };
    });
    
    // 4. 通过ESM HMR API推送（浏览器原生支持）
    this.sendHMRUpdate(updates);
  }
  
  // 浏览器端接收更新
  // Vite客户端代码
  if (import.meta.hot) {
    import.meta.hot.accept((newModule) => {
      // 直接替换模块，保持状态
      updateComponent(newModule);
    });
  }
}
```

# Monorepo 的理解

## 什么是 Monorepo？

**Monorepo**（单一代码仓库）是一种将多个相关项目或包存储在同一个代码仓库中的开发策略。

```javascript
// 传统多仓库（Polyrepo）结构
company/
├── project-a/          # 独立仓库
├── project-b/          # 独立仓库
└── project-c/          # 独立仓库

// Monorepo 结构
company-monorepo/
├── packages/
│   ├── ui-components/ # 包A
│   ├── utils/         # 包B
│   └── api-sdk/       # 包C
├── apps/
│   ├── web-app/       # 应用A
│   ├── mobile-app/    # 应用B
│   └── admin-panel/   # 应用C
├── shared/
└── package.json       # 根配置
```

## Monorepo 解决的问题

### 1. **代码共享和复用**
```javascript
// 问题：多仓库中共享代码困难
// 传统方式：发布到npm或复制粘贴
// project-a/src/utils.js
export const formatDate = (date) => { /* 实现 */ };

// project-b 需要使用时：
// 1. 复制代码（维护困难）
// 2. 发布私有包（流程繁琐）

// Monorepo 解决方案：直接引用
// packages/shared-utils/src/index.js
export const formatDate = (date) => { /* 实现 */ };

// apps/web-app/package.json
{
  "dependencies": {
    "@company/shared-utils": "workspace:*" // 直接引用本地包
  }
}
```

### 2. **依赖管理优化**
```javascript
// 问题：多仓库依赖版本不一致
project-a: react@^17.0.0
project-b: react@^18.0.0  // 版本冲突
project-c: react@^17.0.0

// Monorepo 解决方案：统一依赖管理
// 根目录 package.json
{
  "devDependencies": {
    "react": "^18.2.0",  // 统一版本
    "typescript": "^5.0.0"
  }
}

// 所有子包继承统一版本，避免：
// - 重复安装
// - 版本冲突
// - 安全漏洞
```

### 3. **跨项目重构和协作**
```javascript
// 问题：API变更需要同步多个仓库
// 1. 修改 utils 库的API
// 2. 发布新版本
// 3. 在每个使用项目中更新依赖
// 4. 测试每个项目
// （容易遗漏，耗时耗力）

// Monorepo 解决方案：原子提交
git commit -m "feat: 更新用户认证逻辑
- 更新 @company/auth 包
- 同步修改 web-app
- 同步修改 mobile-app
- 更新所有测试"

// 所有相关修改在一个提交中完成
// CI/CD 可以统一测试和部署
```

### 4. **统一工具链和配置**
```javascript
// 问题：每个项目重复配置
// project-a/.eslintrc.js
// project-a/.prettierrc
// project-a/jest.config.js
// project-a/tsconfig.json
// （重复配置，维护困难）

// Monorepo 解决方案：共享配置
monorepo/
├── configs/
│   ├── eslint-config/     # 共享ESLint配置
│   ├── typescript-config/ # 共享TS配置
│   └── jest-config/       # 共享测试配置
└── packages/
    ├── pkg-a/            # 继承共享配置
    └── pkg-b/            # 继承共享配置
```

### 5. **提高开发效率**
```javascript
// 传统流程：
1. git clone project-a
2. cd project-a && npm install
3. git clone project-b
4. cd project-b && npm install
5. 在两个项目间切换

// Monorepo 流程：
1. git clone monorepo
2. npm install  # 一次安装所有依赖
3. 所有项目立即可用
4. VS Code 等编辑器可以索引所有代码
```

# 微前端的核心价值

## 核心价值

1. **技术栈无关性**：允许不同团队使用不同技术栈（React、Vue、Angular等）
2. **独立开发部署**：每个微应用可以独立开发、测试、部署
3. **渐进式升级**：可以逐步替换旧系统，降低迁移风险
4. **团队自治**：各团队可以独立决策技术选型和发布节奏
5. **增量加载**：按需加载子应用，优化首次加载性能

# 主流微前端方案及优缺点

## 1. **Single-SPA**

### 优点：
```javascript
// 1. 框架无关性
registerApplication({
  name: 'app1',
  app: () => import('app1'), // 可以是React、Vue、Angular等
  activeWhen: '/app1'
});

// 2. 生态成熟
- 丰富的生命周期管理（bootstrap、mount、unmount）
- 完善的工具链（single-spa-webpack-plugin）
- 活跃的社区支持

// 3. 灵活的路由控制
const routes = [
  { path: '/react', app: 'react-app' },
  { path: '/vue', app: 'vue-app' }
];
```

### 缺点：
```javascript
// 1. 样式隔离需要手动处理
// 需要额外配置CSS Modules、Shadow DOM等
import { cssScope } from 'single-spa-css';

// 2. 依赖管理复杂
// 需要手动处理共享依赖，避免重复打包
export const sharedDeps = {
  react: () => import('react'),
  'react-dom': () => import('react-dom')
};

// 3. 配置相对复杂
// 需要为每个应用配置完整的生命周期
const lifecycles = {
  bootstrap: [() => Promise.resolve()],
  mount: [() => mountApp()],
  unmount: [() => unmountApp()]
};
```

### 优点：

### 缺点：

qiankun 的架构基于 **Single-SPA**，但提供了更完整的微前端解决方案：

```javascript
// qiankun 的核心流程
┌─────────────────────────────────────────┐
│           主应用（基座）                  │
│   ┌─────────────────────────────────┐   │
│   │   registerMicroApps()           │   │
│   │   ├── 注册子应用配置             │   │
│   │   └── 设置生命周期              │   │
│   │                                │   │
│   │   start()                      │   │
│   │   ├── 预加载子应用              │   │
│   │   ├── 劫持路由系统              │   │
│   │   └── 初始化沙箱               │   │
│   └─────────────────────────────────┘   │
│                                          │
│   监听路由变化 → 匹配子应用 → 加载执行     │
└─────────────────────────────────────────┘
```

## 一、样式隔离实现原理

### 1. **Shadow DOM 隔离（严格模式）**
```javascript
// 原理：使用 Shadow DOM 的天然隔离特性
class StrictStyleIsolation {
  constructor(container) {
    // 创建 Shadow DOM
    this.shadowRoot = container.attachShadow({ mode: 'closed' });
  }
  
  appendChild(element) {
    return this.shadowRoot.appendChild(element);
  }
}

// 使用
const container = document.getElementById('subapp');
const strictIsolation = new StrictStyleIsolation(container);

// 子应用的样式和DOM都被隔离在Shadow DOM内部
strictIsolation.appendChild(subAppElement);
```

**优点**：
- 完美的样式隔离
- 浏览器原生支持

**缺点**：
- 弹窗等全局组件可能被隔离
- 子应用样式无法影响外部

### 2. **Scoped CSS 隔离（实验性模式）**
```javascript
// 原理：动态修改CSS规则，添加作用域前缀
class ScopedCSS {
  constructor(appName) {
    this.appName = appName;
    this.styleElement = null;
  }
  
  process(cssText) {
    // 为所有CSS规则添加应用名前缀
    const scopedCSS = this.addScope(cssText);
    return scopedCSS;
  }
  
  addScope(cssText) {
    // 使用正则添加作用域
    // 转换 .button { ... } 为 [qiankun-app-name] .button { ... }
    const scope = `[data-qiankun="${this.appName}"]`;
    
    // 处理各种CSS选择器
    return cssText.replace(
      /([^{]*)\{/g,
      (match, selectors) => {
        const scopedSelectors = selectors
          .split(',')
          .map(selector => `${scope} ${selector.trim()}`)
          .join(', ');
        return `${scopedSelectors} {`;
      }
    );
  }
  
  // 动态样式处理
  processDynamicStyle(styleElement) {
    if (styleElement.textContent) {
      styleElement.textContent = this.addScope(styleElement.textContent);
    }
  }
}

// 使用
const scopedCSS = new ScopedCSS('subapp');
const processedCSS = scopedCSS.process(originalCSS);
```

### 3. **运行时样式切换**
```javascript
// qiankun 的实际实现：切换时移除旧样式，添加新样式
class RuntimeStyleHandler {
  constructor() {
    this.appStyles = new Map(); // 存储各应用的样式
  }
  
  // 激活应用时添加样式
  activate(appName) {
    const styles = this.appStyles.get(appName);
    if (styles) {
      styles.forEach(style => {
        if (!style.parentNode) {
          document.head.appendChild(style);
        }
      });
    }
  }
  
  // 失活应用时移除样式
  deactivate(appName) {
    const styles = this.appStyles.get(appName);
    if (styles) {
      styles.forEach(style => {
        if (style.parentNode) {
          style.parentNode.removeChild(style);
        }
      });
    }
  }
  
  // 记录应用的样式
  record(appName, styleElements) {
    this.appStyles.set(appName, styleElements);
  }
}
```

## 二、JavaScript 沙箱实现原理

### 1. **快照沙箱（SnapshotSandbox）**
```javascript
// 原理：激活时记录全局状态，失活时恢复
class SnapshotSandbox {
  constructor(name) {
    this.name = name;
    this.proxy = window; // 直接使用原window
    this.modifyPropsMap = {}; // 记录修改的属性
    this.snapshotWindow = {}; // 快照
  }
  
  // 激活沙箱
  activate() {
    // 1. 记录当前window的快照
    this.snapshotWindow = {};
    for (const prop in window) {
      if (window.hasOwnProperty(prop)) {
        this.snapshotWindow[prop] = window[prop];
      }
    }
    
    // 2. 恢复之前修改的属性
    Object.keys(this.modifyPropsMap).forEach(prop => {
      window[prop] = this.modifyPropsMap[prop];
    });
    
    this.sandboxRunning = true;
  }
  
  // 失活沙箱
  inactivate() {
    // 1. 记录修改的属性
    this.modifyPropsMap = {};
    for (const prop in window) {
      if (window.hasOwnProperty(prop)) {
        if (window[prop] !== this.snapshotWindow[prop]) {
          this.modifyPropsMap[prop] = window[prop];
        }
      }
    }
    
    // 2. 恢复快照
    for (const prop in window) {
      if (window.hasOwnProperty(prop)) {
        window[prop] = this.snapshotWindow[prop];
      }
    }
    
    this.sandboxRunning = false;
  }
}
```

**适用场景**：
- 兼容性要求高（支持IE）
- 同一时间只运行一个子应用

### 2. **代理沙箱（ProxySandbox）**
```javascript
// 原理：使用Proxy代理window，创建隔离的全局环境
class ProxySandbox {
  constructor(name) {
    this.name = name;
    this.running = false;
    
    // 创建一个虚拟的window对象
    const fakeWindow = Object.create(null);
    
    // 记录新增的全局变量
    const addedPropsMap = new Map();
    // 记录修改的全局变量
    const modifiedPropsMap = new Map();
    
    // 代理配置
    const proxy = new Proxy(fakeWindow, {
      set: (target, prop, value) => {
        // 如果沙箱未运行，不处理
        if (!this.running) return false;
        
        // 记录属性设置
        if (!window.hasOwnProperty(prop)) {
          addedPropsMap.set(prop, value);
        } else if (!modifiedPropsMap.has(prop)) {
          // 记录原始值
          modifiedPropsMap.set(prop, window[prop]);
        }
        
        // 更新真实window
        window[prop] = value;
        return true;
      },
      
      get: (target, prop) => {
        // 优先从沙箱自己的fakeWindow中取
        if (prop in target) {
          return target[prop];
        }
        
        // 否则从原始window中取
        const value = window[prop];
        
        // 如果value是函数，需要绑定this
        if (typeof value === 'function' && !value.prototype) {
          return value.bind(window);
        }
        
        return value;
      },
      
      has: (target, prop) => {
        return prop in target || prop in window;
      }
    });
    
    this.proxy = proxy;
    this.addedPropsMap = addedPropsMap;
    this.modifiedPropsMap = modifiedPropsMap;
  }
  
  active() {
    this.running = true;
  }
  
  inactive() {
    this.running = false;
    
    // 清理新增的属性
    this.addedPropsMap.forEach((value, prop) => {
      delete window[prop];
    });
    
    // 恢复修改的属性
    this.modifiedPropsMap.forEach((value, prop) => {
      window[prop] = value;
    });
    
    this.addedPropsMap.clear();
    this.modifiedPropsMap.clear();
  }
}
```

### 3. **多实例代理沙箱**
```javascript
// 支持多个子应用同时运行的沙箱
class MultipleProxySandbox {
  constructor(name) {
    this.name = name;
    this.sandboxRunning = true;
    
    // 每个沙箱独立的fakeWindow
    const fakeWindow = Object.create(null);
    
    // 使用WeakMap避免内存泄漏
    const addedPropsMap = new Map();
    const modifiedPropsMap = new Map();
    const originalValues = new Map();
    
    const proxy = new Proxy(fakeWindow, {
      set: (target, prop, value, receiver) => {
        if (!this.sandboxRunning) return true;
        
        // 如果原始window上没有这个属性，记录为新增
        if (!window.hasOwnProperty(prop)) {
          addedPropsMap.set(prop, value);
        } else if (!modifiedPropsMap.has(prop)) {
          // 记录原始值
          const originalValue = window[prop];
          originalValues.set(prop, originalValue);
          modifiedPropsMap.set(prop, value);
        }
        
        // 设置到沙箱的fakeWindow中
        target[prop] = value;
        return true;
      },
      
      get: (target, prop, receiver) => {
        // 屏蔽一些危险操作
        if (prop === 'window' || prop === 'self' || prop === 'globalThis') {
          return proxy;
        }
        
        if (prop === 'top' || prop === 'parent') {
          // 如果是iframe环境，返回parent，否则返回proxy
          if (window.parent !== window) {
            return window.parent;
          }
          return proxy;
        }
        
        // 优先从沙箱自身获取
        if (target.hasOwnProperty(prop)) {
          return target[prop];
        }
        
        // 从原始window获取
        const value = window[prop];
        
        // 处理函数绑定
        if (typeof value === 'function') {
          // 一些原生函数需要特殊处理
          if (prop === 'eval' || prop === 'Function') {
            return (...args) => value.apply(window, args);
          }
          
          // 绑定this到proxy
          return value.bind(window);
        }
        
        return value;
      },
      
      has: (target, prop) => {
        return prop in target || prop in window;
      },
      
      getOwnPropertyDescriptor(target, prop) {
        if (target.hasOwnProperty(prop)) {
          return Reflect.getOwnPropertyDescriptor(target, prop);
        }
        
        if (window.hasOwnProperty(prop)) {
          return Reflect.getOwnPropertyDescriptor(window, prop);
        }
        
        return undefined;
      }
    });
    
    this.proxy = proxy;
  }
  
  active() {
    this.sandboxRunning = true;
  }
  
  inactive() {
    this.sandboxRunning = false;
  }
}
```

### 4. **沙箱的额外处理**

#### a) **定时器隔离**
```javascript
class TimerSandbox {
  constructor() {
    this.timeoutIds = new Set();
    this.intervalIds = new Set();
  }
  
  // 劫持setTimeout
  hijackTimers() {
    const originalSetTimeout = window.setTimeout;
    const originalSetInterval = window.setInterval;
    const originalClearTimeout = window.clearTimeout;
    const originalClearInterval = window.clearInterval;
    
    window.setTimeout = (handler, timeout, ...args) => {
      const timerId = originalSetTimeout(() => {
        handler(...args);
        this.timeoutIds.delete(timerId);
      }, timeout);
      
      this.timeoutIds.add(timerId);
      return timerId;
    };
    
    window.setInterval = (handler, timeout, ...args) => {
      const intervalId = originalSetInterval(() => {
        handler(...args);
      }, timeout);
      
      this.intervalIds.add(intervalId);
      return intervalId;
    };
    
    window.clearTimeout = (id) => {
      this.timeoutIds.delete(id);
      originalClearTimeout(id);
    };
    
    window.clearInterval = (id) => {
      this.intervalIds.delete(id);
      originalClearInterval(id);
    };
  }
  
  // 清理所有定时器
  clear() {
    this.timeoutIds.forEach(id => window.clearTimeout(id));
    this.intervalIds.forEach(id => window.clearInterval(id));
    this.timeoutIds.clear();
    this.intervalIds.clear();
  }
}
```

#### b) **事件监听器隔离**
```javascript
class EventListenerSandbox {
  constructor() {
    this.eventListeners = new Map();
  }
  
  hijackEventListeners() {
    const originalAddEventListener = window.addEventListener;
    const originalRemoveEventListener = window.removeEventListener;
    
    window.addEventListener = (type, listener, options) => {
      if (!this.eventListeners.has(type)) {
        this.eventListeners.set(type, new Set());
      }
      
      this.eventListeners.get(type).add(listener);
      originalAddEventListener.call(window, type, listener, options);
    };
    
    window.removeEventListener = (type, listener, options) => {
      const listeners = this.eventListeners.get(type);
      if (listeners) {
        listeners.delete(listener);
      }
      originalRemoveEventListener.call(window, type, listener, options);
    };
  }
  
  // 移除所有事件监听器
  clear() {
    this.eventListeners.forEach((listeners, type) => {
      listeners.forEach(listener => {
        window.removeEventListener(type, listener);
      });
    });
    this.eventListeners.clear();
  }
}
```

## 三、qiankun 的完整加载流程

```javascript
// 简化的加载流程
class QiankunLoader {
  async loadApp(appConfig) {
    // 1. 创建沙箱
    const sandbox = this.createSandbox(appConfig.name);
    
    // 2. 获取HTML入口
    const { template, scripts, styles } = await this.fetchEntry(appConfig.entry);
    
    // 3. 样式隔离处理
    const processedStyles = this.processStyles(styles, appConfig.name);
    
    // 4. 执行JS代码（在沙箱中）
    const exportLifecycles = await this.execScripts(
      scripts,
      sandbox.proxy,
      appConfig.name
    );
    
    // 5. 获取子应用生命周期
    const { bootstrap, mount, unmount } = exportLifecycles;
    
    // 6. 挂载应用
    const container = document.querySelector(appConfig.container);
    await mount({
      container,
      props: appConfig.props
    });
    
    return { unmount, sandbox };
  }
  
  createSandbox(name) {
    // 根据配置选择沙箱类型
    if (window.Proxy) {
      return new MultipleProxySandbox(name);
    } else {
      return new SnapshotSandbox(name);
    }
  }
  
  async execScripts(scripts, proxy, appName) {
    // 构造执行环境
    const execContext = `
      (function(window, self, globalThis){
        ${scripts.join('\n')}
      }).bind(window)(window, window, window);
    `;
    
    // 在沙箱中执行
    const wrappedCode = `
      with(window.__SANDBOX_PROXY__) {
        ${execContext}
      }
    `;
    
    // 设置沙箱代理
    proxy.__SANDBOX_PROXY__ = proxy;
    
    // 执行代码
    const execScript = new Function('window', wrappedCode);
    execScript(proxy);
    
    // 获取导出的生命周期
    return proxy.__POWERED_BY_QIANKUN__;
  }
}
```

## 五、总结

**qiankun 的实现核心：**

1. **样式隔离**：
   - **Shadow DOM**：完美的隔离，但有兼容性问题
   - **Scoped CSS**：运行时添加作用域前缀，兼容性更好
   - **动态切换**：应用切换时动态添加/移除样式表

2. **JavaScript 沙箱**：
   - **SnapshotSandbox**：快照/恢复模式，兼容性好但性能较差
   - **ProxySandbox**：基于Proxy的代理模式，性能好但需要现代浏览器
   - **多实例沙箱**：支持多个子应用同时运行
   - **额外隔离**：定时器、事件监听器等副作用的隔离

3. **加载机制**：
   - 通过 `import-html-entry` 解析HTML入口
   - 动态创建脚本和样式标签
   - 在沙箱环境中执行子应用代码

**qiankun 的优点**：
- 完整的微前端解决方案
- 完善的沙箱机制
- 良好的社区生态
- 生产环境验证充分

**注意事项**：
- 子应用需要适配（修改入口和webpack配置）
- 样式隔离不是100%完美
- 某些特殊场景可能需要额外处理（如WebGL、WebWorker等）
