## websocket心跳要怎么做，传递用户信息用什么
WebSocket 心跳机制实现：
1. 定时发送心跳包 ：客户端每 30-60 秒向服务器发送一个简单的心跳消息（如 { "type": "ping" } ）。
2. 服务器响应 ：服务器收到心跳后回复 { "type": "pong" } 确认连接。
3. 超时重连 ：客户端设置超时时间（如 10 秒），若未收到 pong 则认为连接断开，触发重连逻辑。
4. 连接状态管理 ：服务器通过心跳检测清理无效连接，避免资源浪费。
传递用户信息的方式：
1. URL 参数 ：连接时通过 URL 携带用户标识，如 ws://example.com/ws?userId=123 。
2. HTTP 头 ：握手阶段使用 Authorization 头传递 token（如 JWT）。
3. 自定义消息 ：连接建立后，发送包含用户信息的初始化消息（如 { "action": "init", "user": { ... } } ）。
4. 连接映射 ：服务器将 WebSocket 连接与用户 ID 绑定，存储在内存或 Redis 中，后续通过连接识别用户。

## 大模型传输数据websocket的数据格式和sse的区别
数据格式与传输方式：
1. WebSocket ：
   - 全双工通信，支持双向实时传输
   - 数据格式灵活，可自定义 JSON、Protocol Buffers 等
   - 适用于需要频繁交互的场景（如聊天、实时问答）
   - 连接建立后持续保持，数据可分段发送（如流式输出）
2. SSE (Server-Sent Events) ：
   - 单向通信，仅服务器向客户端推送
   - 基于 HTTP 协议，使用文本格式，默认事件流格式为 event: type\ndata: message\n\n
   - 适合单向数据流（如大模型生成结果的持续输出）
   - 无需额外协议，兼容性更好，可通过 HTTP 缓存优化
适用场景对比：
- WebSocket ：大模型需要实时交互（如多轮对话、实时编辑），双向通信场景
- SSE ：大模型仅需单向输出（如文本生成、代码生成），服务端推送场景

## http1.0 http1.1 http2的区别
1. 连接管理
- HTTP 1.0 ：每次请求都建立新连接（无连接），完成后断开
- HTTP 1.1 ：引入持久连接（Keep-Alive），同一连接可处理多个请求
- HTTP 2.0 ：多路复用，单个连接可并发处理多个请求和响应
2. 性能优化
- HTTP 1.0 ：无优化，每次请求都需完整握手
- HTTP 1.1 ：
  - 管道化（Pipelining）：同一连接可发送多个请求，但需按序响应
  - 分块传输编码（Chunked Transfer Encoding）：支持动态内容传输
- HTTP 2.0 ：
  - 二进制分帧：将数据分割为小帧，乱序发送，有序重组
  - 头部压缩：使用 HPACK 算法压缩头部，减少传输体积
  - 服务器推送（Server Push）：主动推送相关资源
3. 安全性
- HTTP 1.0 ：默认明文传输，无强制加密
- HTTP 1.1 ：支持 HTTPS，但非强制
- HTTP 2.0 ：建议与 TLS 配合使用，主流浏览器仅支持加密的 HTTP 2.0
4. 功能特性
- HTTP 1.0 ：基本的 GET、POST、HEAD 方法
- HTTP 1.1 ：新增 PUT、DELETE、OPTIONS 等方法，支持 Host 头
- HTTP 2.0 ：保持 HTTP 语义，仅优化传输层

## 跨域是什么，常见的解决方案 
跨域（Cross-Origin Resource Sharing, CORS）是指在浏览器中，当一个网页的脚本尝试从不同源（协议、域名或端口）加载资源时，会触发浏览器的同源策略（Same-Origin Policy），导致跨域问题。
常见的解决方案包括：
1. JSONP ：利用 `<script>` 标签的跨域能力，通过动态创建 `<script>` 标签加载资源，服务器返回函数调用，实现跨域数据获取。
2. CORS ：服务器端设置响应头 Access-Control-Allow-Origin ，允许指定源访问资源。
3. 代理服务器 ：在同源服务器上设置代理，将跨域请求转发到目标服务器，绕过浏览器的同源策略。
4. 跨域 POST 请求 ：通过表单提交或动态创建 `<iframe>` ，将 POST 请求转换为 GET 请求，绕过浏览器的同源策略。
