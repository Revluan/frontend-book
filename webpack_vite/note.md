## tree-shaking是怎么做的
Tree-Shaking 是一种通过静态分析消除未使用代码的优化技术，得名于将代码想象成一棵树，摇晃它使未使用的代码（死代码）掉落。
1.静态分析
- 基于 ES6 模块系统 ：Tree-Shaking 依赖于 ES6 的 import 和 export 语法，因为它们是静态的，可以在编译时确定依赖关系
- AST 解析 ：构建工具（如 Webpack、Rollup）会解析代码生成抽象语法树(AST)，分析模块间的依赖关系
2.标记阶段
- 标记未使用的导出 ：分析每个模块的导出，标记哪些导出被其他模块使用
- 依赖追踪 ：从入口文件开始，追踪所有被使用的导入和导出
3.消除阶段
- 删除未使用代码 ：在代码生成阶段，删除所有未被标记为使用的导出
- 代码压缩 ：结合 Terser 等压缩工具，进一步优化代码体积

## 打包工具webpack,vite,rollup的区别
设计目标与适用场景：
1. Webpack ：
   - 定位：通用型打包工具，适用于大型应用
   - 场景：复杂单页应用（SPA）、多页应用，需要处理多种资源（JS、CSS、图片等）
   - 特点：支持代码分割、动态导入，插件生态丰富
2. Vite ：
   - 定位：现代前端构建工具，强调开发体验
   - 场景：中小型应用、快速开发迭代，支持 Vue、React 等框架
   - 特点：开发环境使用原生 ESM（浏览器直接加载），生产环境使用 Rollup 打包
3. Rollup ：
   - 定位：专注于库和组件的打包
   - 场景：第三方库、工具库、组件库的构建
   - 特点：Tree-Shaking 能力强，输出代码体积小、更简洁

## 组件库，按需加载怎么做的，具体打包配置了什么
基于 ES6 模块的静态分析能力，构建工具（如 Webpack、Vite）通过 Tree-Shaking 消除未使用的组件代码，只打包实际导入的组件。
组件库的打包配置：
1. 使用 Rollup 构建 （推荐）：
   - 配置 output.format: 'es' ，生成 ES 模块格式
   - 启用 preserveModules: true ，将每个组件打包为独立文件
   - 配置 external 排除第三方依赖（如 Vue、React），避免重复打包
2. 目录结构设计 ：
   - 每个组件独立目录，包含 index.js （组件逻辑）和 style.css （组件样式）
   - 根目录 index.js 导出所有组件（供全量导入）
   - 支持 import { Button } from 'component-lib' 和 import Button from 'component-lib/es/button' 两种导入方式
3. CSS 按需加载 ：
   - 方案一：组件内通过 import './style.css' 导入样式，构建工具自动处理
   - 方案二：使用 babel-plugin-import 等插件，在编译时自动注入样式导入
   - 方案三：提供独立的样式文件，用户可选择全量引入或按需引入
